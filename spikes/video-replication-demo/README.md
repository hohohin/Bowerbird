# 视频复刻独立 Demo

用于验证：抖音链接 → 获取原视频 → 豆包语音文字及时间戳 → 抽帧分析分镜 → 替换台词／人物／产品 → 按镜头生成 → 实际语音对齐 → 本机字幕合成。独立 Node 服务。

**Seedance 输入视频数量固定为 0。** 原片只用于本机取音频、抽帧和对照；生成接口拒绝视频附件。原片抽帧也不传给 Seedance，生成只提交分镜文字和用户上传的替换图片。

## 启动与配置

Windows 双击 `start-demo.cmd`，浏览器打开 `http://127.0.0.1:1768`。也可以在此目录执行 `npm start`。需要 Node.js 22+、Chrome 或 Edge、本机 FFmpeg／ffprobe、Codex 与即梦官方 CLI，以及 Bowerbird 中已有的两项订阅登录。

本仓库运行时可直接使用 `apps/html-renderer/node_modules/playwright`。单独复制此目录运行时，先执行 `npm install`。FFmpeg 优先查找显式路径、仓库现有工具和 PATH；即梦优先查找显式路径、用户 `bin` 和 PATH。缺少时可在页面「服务配置」填写程序绝对路径。服务只监听 `127.0.0.1`，不要作为公网服务部署。

豆包语音 Key 填在本目录 `.env.local`：

```dotenv
DOUBAO_SPEECH_API_KEY=你的豆包语音Key
DOUBAO_SPEECH_RESOURCE_ID=volc.bigasr.auc_turbo
```

也可在页面配置。密码框留空会保留旧 Key，服务端不会将 Key 回传浏览器。旧控制台可改填 `DOUBAO_SPEECH_APP_ID` 与 `DOUBAO_SPEECH_ACCESS_TOKEN`。需要开通「录音文件识别极速版」。这里使用的是豆包语音 Key；生成阶段使用本机即梦订阅，无需 `ARK_API_KEY`。

Windows 即梦通过 Bowerbird 已安装的私有 `cli-launcher.exe`／注册表隔离层运行，沿用应用中的即梦授权。画面分析通过本机 Codex CLI，使用 Bowerbird 的私有 Codex 登录。程序通常自动发现，也可在页面配置 `CODEX_BINARY`／`JIMENG_BINARY`。若尚未登录，请先在 Bowerbird 完成对应登录。Demo 不读取、复制或导出 OAuth 内容。

## 操作

1. 粘贴抖音分享文案或视频链接，点击获取。会打开专用采集窗口，需要登录时可在该窗口操作。独立浏览器资料保存在 `data/douyin-profile`。
2. 点击豆包转写。结果提供原文、句子时间戳、服务实际返回的词级时间戳，以及 JSON／SRT 下载。点击时间可以定位原视频。无音轨视频可直接确认空转写。
3. 点击视觉拆解。在本机提取最多 12 张、最长边 768 像素的静态画面，连同转写文字交给 Codex，取得镜头结构、主体、场景、构图与动作描述。分析结果保存后复用。
4. 在分镜中修改画面、摄影、动作和台词，也可逐句替换。单镜头可填完整新台词；跨镜头台词没有完整词级时间时，需明确分配到各镜头。人物／产品图片库不限数量，每张不超过 10 MB。上传后在每个镜头内分别勾选人物和产品，可多选或不选；不会自动应用到所有镜头。单镜头最多 30 张，遵循本机即梦 CLI 限制。
5. 查看制作计划后生成。每镜头只发送该镜头所选图片，图片编号对应选择顺序，计划列出文件名和用途。未选图走 `text2video`，有图走仅含 `--image` 的 `multimodal2video`；均使用本机即梦 `seedance2.5`、720p。每个镜头 4–15 秒，逐镜头保存提交编号和结果，再本机拼接。
6. 有计划台词时，从新视频提取音轨，再通过豆包识别实际口播及时间戳，最后 FFmpeg 叠加字幕。提供成片、实际语音 JSON 和字幕 SRT。缺时间戳会停止并允许仅重试语音步骤；字幕失败时复用已有有效转写。

支持 4–120 秒参考视频，最多 24 个语义镜头段。稀疏抽帧不能证明所有精确切点、快速动作和转场，因此分镜可人工校正，未确认的细节会注明。镜头生成时长向上取整到整秒，最终时长可能略长于原片。

这是「分析 → 分镜 → 素材生成 → 合成」的 Demo，没有完整实现 Hypit 的 SVML、词语挂钩、独立 B-roll 与特效调度。镜头画面、声音和口型仍由模型生成；台词识别差异会提示用户试听，不自动重投。人物跨镜头一致性、产品细节和整体复刻质量仍需成片验收。

本方案移除了 Seedance 的参考视频输入消耗，但不承诺总额度固定减半：仍有 Codex 图片分析、即梦镜头生成及豆包原声／新声识别，具体消耗取决于素材数量和输出时长。

## 保存与恢复

任务位于 `data/tasks/<任务ID>/`：原片、音轨、缩略图、原声转写、分析抽帧及分镜、替换图片、任务状态和每次生成的冻结计划及结果。刷新页面会恢复任务。提交后即刻保存 `submit_id`；中断后「继续原任务」使用冻结参数查询原编号，复用已完成镜头，再继续后处理。未完成任务必须先恢复，完成或明确失败后才能生成新版本。提交结果未知且未取得编号时会阻止再次提交，需人工核对即梦任务历史。

已有旧版成片保留。旧版中断任务只查询已提交的编号，停止未提交的原视频片段；之后可完成视觉分析并生成新版本。

镜头的图片选择随草稿保存及重开恢复。移除图片会清除当前编辑中的关联；已经提交的生成版本仍保留自己的图片和顺序，恢复时不受后续编辑影响。升级前没有逐镜头选择的草稿默认未选图，需在镜头中勾选；已有运行中的冻结版本继续使用原参数。

`.env.local`、`data/` 和 `test-output/` 均已忽略，不应提交。各步骤发送范围：豆包接收音频；Codex 接收小尺寸抽帧和转写文字；即梦接收分镜文字和用户替换图。原始视频文件留在本机。

## 代码来源与接口

- 采集脚本移植自 `apps/desktop/src-tauri/src/commands/video_replication/douyin_capture.js` 与 `douyin_quiet.js`；独立 Node 浏览器／下载包装层在 `lib/douyin.mjs`。
- 即梦参数及 Windows 私有登录环境对应应用 `codex/jimeng_video.rs`、`cli_credentials.rs`，实现位于 `lib/generation.mjs`。
- 本机 Codex 私有环境对应应用 `codex_cli.rs`、`cli_credentials.rs`、`local_chat.rs`，分析适配器位于 `lib/analysis.mjs`；使用临时空工作目录、只读沙箱、关闭 shell／MCP／skills，直接输出分镜 JSON。
- [豆包语音录音文件极速版文档](https://docs.volcengine.com/docs/DoubaoVoice/recording-file-recognition-lite-http?lang=zh)：音频 Base64 直接调用极速版 HTTP，不需要将音频放到公网对象存储。
