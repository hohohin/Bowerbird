## Mac 适配与待验收

- 沿用仓库已有 `cc`／Objective-C ARC 桥接，在 `macos/external_drag.m` 实现原件 `NSURL` 列表拖出；Rust 包装仅在主线程获取 `ns_window`。未引入整套拖放插件或新增 Rust 依赖，也不制作临时原件副本。预览使用 48px 系统文档图标，不解码源媒体。
- 源只允许 Copy，忽略修饰键改变操作；委托由主线程单会话状态保活，启动失败、取消和系统接收经同一回调完成，释放 Rust oneshot sender。错误字符串在回调内立即复制，文件路径由 Objective-C 在调用期内转为自持有对象。原生项目／图标／事件准备完毕后，先通过一次性 `before_start` 核对本次准备会话仍有效，再检查普通拖动的实际左键状态，之后才交给 AppKit；取消的旧会话不能借用后续按下重新启动。
- pickup 借鉴 [drag-rs Mac 源码](https://github.com/crabnebula-dev/drag-rs/blob/v2/crates/drag/src/platform_impl/macos/mod.rs) 的局部 `LeftMouseDragged` 事件参数；没有投递全局输入，也没有把该模式改成必须按住。上游没有提供「菜单松手后携带、下一次点击放下」的已核实实测证据；本地 Mac SDK／实机不可用，两种模式均未编译或原生验收，尤其不能将 pickup 源码存在记为行为通过。
- 静态复核了 C/Rust ABI、所有启动退出路径、字符串借用与委托生命周期；单文件 rustfmt 在当前沙盒返回路径访问拒绝，随后由主代理在普通权限下格式化通过。Windows 的 Rust 检查会排除 `cfg(macos)` 代码，不能替代 Mac 构建。

Mac 接收后的最小验收：

1. Intel 与 Apple Silicon 分别编译当前源码，确认静态桥接符号与 AppKit 链接；只使用隔离库和合成素材。
2. 单个／多个中文与空格路径图片、视频、音频拖到 Finder 与目标应用，确认接收的是原件路径，原件内容与位置不变；重复分身只带真实原件。测试窗口切换与普通画板拖动回归。
3. 准备期间松开鼠标应取消；Esc、目标拒绝与正常投放后均恢复可再次拖动，回调只完成一次。系统接收仅证明目标接受协议，不等于剪辑或上传已完成。
4. 单独验证 pickup：菜单鼠标已经松开，移动到其他应用，再次点击投放，确认只收到一次原件；另验 Esc 与失败后的状态恢复。若不成立，保留为未完成的 Mac 交互差异，不悄悄替换为按住拖动。
