# 画板工作流实现与验收

产品范围以 `PROJECT.md`「画板工作流」约定为准。本文记录首版实现契约，不代表安装包或线上发布。

## 操作

### 模板库、参数化子流程与文件分享（2026-09-24，源码未发布）

- 保存入口为「画板框选 → 右键存为模板 → 确认面板 → 保存」。混合选区在图片、内容卡、工作流卡和画板空白处右键均保留选区。面板只填写名称、选择「带上素材」「带上文本」，默认两项勾选；文本指内容卡输入文案，工作流操作指令始终保留。确认时冻结步骤及输入值；取消不保存，失败保留面板和选项可重试。工具栏「工作流模板库」负责搜索、复用、参数编辑、版本管理和导入/导出，不再展示重新勾选步骤的清单。
- 选区保存 1–23 张执行卡片，自动补统一触发器；支持指令、文本改写 Agent、生成、技能和从输入提炼视觉规范。外部文本/图片连线转换成公开必填输入，内部连线和 prompt 引用转为可移植别名。内容卡作为输入来源，隐藏写入器与工作流助手不封装；个人已确认规范绑定必须改为包含提炼步骤，不能把账号 ID 分享出去。
- 参数界面可公开各有效 prompt 步骤的「附加要求」以及生成步骤的「画面比例」，支持名称和默认值。附加要求作为纯文本追加，不允许注入内部引用语法；反推的覆盖已有描述选项也随模板保留。默认公开末端步骤的输出；实例入口能定位内部步骤和实际输出端口，继续连接现有工作流。
- 未携带的输入在添加实例前绑定当前画板的图片、内容单元格或现有卡片输出；已携带的输入默认使用模板内容，也可换成接收者自己的来源。添加时把内容恢复为新的原生内容卡并重新连线，不沿用发送者 ID；实例快照不重复存储图片字节。采用接收者当前 provider，文本改写 Agent 使用既有 Cloud 通道。导入/添加不会自动执行，素材导入跳过自动识图/命名，运行仍使用现有触发器、调度、暂停与恢复。
- 子流程为静态展开式实例：入口卡保存模板版本快照、成员 ID、参数/输入与定义指纹，内部卡片保持可见可编辑。统一重新配置保持成员 ID、位置和生成历史，清除旧输出及下游缓存；步骤手工编辑/删除、运行锁定或形成循环时拒绝覆盖。更新库中模板只影响未来实例。可选择多个实例的内部步骤再封装；尚无折叠、动态嵌套调用或自动同步升级。普通剪贴板复制会解除统一配置身份，避免复制入口误操作原成员。
- 分享：`.bbworkflow.json` 使用 schema v2，并兼容 v1。可选输入正文和 PNG/JPEG/WebP/GIF/BMP 原图 base64 随文件携带，不含原素材 ID、磁盘路径、会话/任务/个人规范绑定或 provider 配置；未携带内容仅保留输入接口。总文件最多 32 MB、单图 base64 最多 1200 万字符、单输入最多 48 图、正文最多 32000 字，超限明确拒绝，不截断。接收者导入为新模板身份，不覆盖本地同名模板；添加实例时才把图片入库并创建内容卡。没有在线分享服务。
- SQLite `0033_workflow_templates.sql` 保存带 revision 的定义，写入/删除检查预期版本，防止旧窗口覆盖。前端复用既有编排编译器校验端口、引用、环路和数量；后端白名单与版本事务阻止不支持字段和并发覆盖。实例仍随 `canvas_workflows` 保存，不开第二套执行数据库。
- 验证：`scripts/canvas-workflow-templates.test.mjs` 完成 34 项逻辑检查，UI 覆盖真实混合框选、图片/工作流右键、保存确认、取消、保存失败重试、素材/文本四种组合、操作指令保留、含附件导出/导入与新内容卡还原；保留参数编辑、搜索、重载、版本、删除不影响实例与原执行器模拟完整运行检查。模板 Rust 2 项通过，包含 v2 内容往返、旧 v1 兼容、私有字段/远程 URL/非法图片拒绝；混合选区 100%/50% 回归、TypeScript/Vite 构建通过。未操作真实素材库、调用付费模型、运行原生文件对话框或发布安装包。

代码入口：`SaveWorkflowTemplateDialog.tsx`、`WorkflowTemplateLibrary.tsx`、`workflowTemplates.ts`、`workflowTemplateContent.ts`、`commands/workflow_templates.rs`；现有 `CanvasWorkflowLayer` 与执行器复用。

后端追加验证：工作流存储回归 13 项（含实例快照往返）与模板库存储 1 项通过，共 14 项，均使用隔离内存 SQLite。新命令和 `0033` 迁移需要重新加载新编译的桌面后端，仅前端热更新不足；尚未进行原生桌面验收。

### 草稿修订与真实存档恢复（2026-09-23，源码未发布）

- 实际请求 `1790176817959-e01e4236-7212-46de-bab4-0197ee4e0d9f`：第一版因 generation 同时声明 inputs.image 与 prompt 引用被拒，Agent 随后改写同一 revision，旧接收器直接 failed；结果文件已前进到第二版，桌面仍停在第一版。草稿版本冲突/跳号现在返回带下一版本号的拒绝反馈并继续等待；不会覆盖原校验记录，不允许用被拒内容的 digest 提交。三版预算、最终提交一致性、取消与来源变化保护仍保留。旧版本造成的同版本改写失败可由「取回修订后的原请求」继续同一 requestId。
- 真实 revision 346 的只读重放又发现持久化边界问题：Rust serde_json 会排序对象字段，但 contextKey 旧字符串与新构造来源使用不同键顺序，导致完全相同的绑定被误判变化。需求及来源快照现在按对象键规范化比较，保留数组顺序；兼容已保存的旧 contextKey，真实值/数组顺序变化仍拒绝。
- 编译器聚合独立卡片诊断，避免一次只报一个问题用尽修订次数。实际第二版同时报告 profile 卡使用非法占位符和未接入最终交付；反馈读写遇到暂时错误或文件恰好换版时，在原有有界轮询内继续取回，不重发模型请求。
- 验证：协议回归扩展至50项；以真实存档与第二版原文在隔离内存重放，恢复后正确反馈上述两项错误；移除无用 profile 的第三版经 proposal/commit 成功编译11张卡（含4张生成卡）。此为隔离修订样本，未改写真实数据库、队列结果或调用模型，不表示真实画板已恢复或出图成功。

### 编排协议与编译器重整（2026-09-23，源码未发布）

- 根因证据：请求 `1790175111982-33274a5f-9d63-4357-97c8-d0eda598a691` 的 DSH 先发布结果文件，随后才自检、补上 `c4` 的 `{{c3.text}}`；桌面已在第一版进入终态，后续修订不再读取。原子重命名只能防止读取半个文件，不能表示语义上的完成。该方案还包含无用产品分析分支，并把四张版式汇成单张交付。
- 新请求使用 `planning-v2`；方案为 `{schemaVersion:2,summary,sourceUses,nodes,outputs}`。生成/文本 Agent 的图文连线只由 prompt 引用编译，其他卡显式声明 `inputs`；模型不再同时写两套连线，也不负责生成触发器。应用保留既有端口、环路、数量、原始来源身份及真实卡片校验，使用现有执行器。
- `sourceUses` 声明每路顶层来源的版式/主体/文案/参考用途与 each/shared 模式；`outputs` 声明最终交付。每张工作卡必须通往交付，拦截死分支；each 模式逐个检查子来源、独立交付和版式原图直连，共享产品/文案必须进入每份 each 交付的依赖路径。助手显示实际编译的交付数量、名称及来源用途。模型选择的用途/模式仍需对照用户意图；校验不证明视觉效果或自然语言理解正确。
- 结果信封 v2：`proposal` 携带 requestId/revision/text；桌面用同一编译器校验，先持久化草稿，再将 `{requestId,revision,digest,valid,error}` 原子写入 `feedback/<requestId>.json`，digest 为原始 text 的 SHA-256。Agent 根据真实错误递增 revision，最多三版；通过后提交同一 text/revision/digest 的 `commit`。未经校验、改写同一版本、伪造最终提交或内容不一致均不落卡。不是依赖文件稳定时长的 debounce。
- 只有 commit 可将新卡片与 applied 标记放入一次 revision 校验保存。回包时再次核验需求/来源；取消拒绝迟到回包；保存失败保留同一批卡片供原保存队列重试；草稿校验失败不立即终止请求，反馈 I/O 失败保留可取回状态。自动取回最多约5分钟，超时/重载可手动取回；DSH 若已结束等待，需要继续原会话读取反馈，桌面不自动重复投递模型请求。
- v1 文本改写通道与历史编排结果保持兼容；旧版 failed 编排可通过「取回修订后的原请求」重新读取同一请求，重做来源及计划校验，不重发模型任务。历史 v1 方案沿用原校验，不隐式升级为 v2 语义。
- 隔离验收：新增 `canvas-workflow-planner-protocol.test.mjs` 35 项检查（四页来源/交付、无用步骤、提示词编译、修订、确认、身份与内容、重载、取消、反馈失败、保存失败、迟到投递回执、旧请求恢复）；原助手48项、引用8项、Rust Agent DS 10项、TypeScript 与生产构建通过。未操作真实桌面、改写用户素材库或触发模型生成；真实 DSH v2 往返与最终出图仍待验收。

### 删除卡片后的保存阻断修复（2026-09-23，源码未发布）

- 生成卡连接内容卡后会有隐藏 `text` writer。原卡片删除入口只过滤输入连线，留下输入为零的 writer，违反后端「writer 恰好一个输入」校验；失败的保存队列继续拒绝后续操作，表现为所有工作流编辑都提示「工作流数据无效」。
- 删除工作流卡时同步移除断开的空 writer 及其引用；普通下游卡片保留，内容卡已存文字/图片不修改。「重试保存」先清理同类历史残留，再重试当前内存文档，不刷新、不用旧存档覆盖后续未保存编辑。锁定检查与原有 revision 校验保留。

### 工作流助手需求中的输入引用（2026-09-23，开发版）

- 需求框复用生成卡片的 `WorkflowPromptEditor`，按 `@` 从已接入的文本/图片中插入引用标签，沿用缩略图、文本预览、编辑撤销与持久化；等待编排时禁用编辑。原有纯文本需求仍可提交，接入的其他来源仍供编排选择。
- 投递前将内部 `@[UUID]` 按来源绑定转换成 `【sourceN.text/image：显示名称】`，与能力上下文中的来源别名对应，让 Agent 读懂句中每个输入的用途。显式引用的文本发送完整内容，不再截成 600 字；整个上下文仍有 16 KB 上限，过长时明确要求减少来源。图片引用只传已有来源元数据，不宣称模型已看图。
- 未知或断开的引用在送达前拒绝；请求快照包含活动引用的绑定，等待中改绑引用后不能落入旧计划。复制沿用画板既有引用重映射，删除引用标签不会把内部 token 发给模型。
- `canvas-workflow-planner-references.test.mjs` 覆盖真实 `@` 菜单插入、图文混排、重载、发送别名及完整文本、等待禁用、取消、复制、失效引用阻断与旧回复保护；沿用助手、生成引用、初始化拖动回归和 TypeScript/构建验证。
