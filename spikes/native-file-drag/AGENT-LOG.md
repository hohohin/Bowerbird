# Native file drag feasibility

- Read current project/UI/source-file rules, Windows build contract, existing Windows 0.61/WebView2 bindings. Sources must remain in place; COPY is offered as a receiver transfer effect, never a Bowerbird original-file duplication.
- Read Microsoft IDropSource::QueryContinueDrag, DoDragDrop and WebView2 CompositionController5::DragStarting, plus CrabNebula drag-rs Windows implementation. Click pickup needs a custom continuation state; the mature default immediately drops without a held left button. WebView2 DragStarting is composition-controller-only and absent in current 0.38.2 bindings, not a drop-in route for the existing windowed WebView.
- Start isolated spike with the normal release-to-drop implementation, then require pickup to remain active without any held button and complete after the next click. No global mouse injection is part of product logic. This spike has no access to user library, network transfer, credentials or target application accounts.
- Actual RED: pickup-with-no-button returned Drop instead of Continue; corrected the two-phase continuation state. Ordinary hold, pickup next-click and cancellation tests now pass.
- Actual native IDataObject RED: an empty shell object rejected CF_HDROP with HRESULT 0x80040064. Building a shell item array from original paths and binding BHID_DataObject now delivers both Unicode and ASCII synthetic paths; source bytes remain unchanged. All 4 tests pass offline.
- Added optional shell icon drag image using SIIGBF_ICONONLY, avoiding original media decoding. Bitmap and PIDL ownership are released; OleInitialize/OleUninitialize are scoped to the caller thread, not a process-global Once.
- Added isolated Tauri example + same-WebView HTML drop target and separate Windows Forms native file receiver. These are test-only; real pointer operations will use the computer-use skill, not product-side fake input.
- Actual RED: an asynchronously prepared ordinary drag started after mouse release returned Drop; changed the initial unpressed hold state to Cancel and check the current physical button immediately before DoDragDrop. Pickup remains unpressed until its next complete click.
- Actual RED using resolver-shaped fs::canonicalize paths: Shell rejected verbatim Windows paths with E_INVALIDARG (0x80070057). Existing connection path spelling code is private; the isolated Windows adapter converts typed VerbatimDisk/VerbatimUNC prefixes to ordinary Shell paths, preserving server/share and OsString characters. Native CF_HDROP data resolves back to the same synthetic originals. All 6 tests pass; the initial sandbox canonicalize AccessDenied was an environment failure, not the product RED.
- Rebuilt the isolated Tauri example after adding Win32_UI_Input_KeyboardAndMouse and removing its unused import. Shared main target lock belonged to another build; waited without changing or terminating it.
- Moved the verified Windows implementation into `apps/desktop/src-tauri/src/external_drag.rs` and `external_drag/windows.rs` after UI adoption. The isolated crate and Tauri example now include that exact production module; explicit submodule paths keep the inclusion working. Root owns session/cancellation commands and Mac agent owns the Mac adapter.
- Added the `before_start` callback immediately before the physical button guard/DoDragDrop so root's session ownership check can atomically reject cancelled preparation without a new mouse press reviving it. Root covers the session behavior with three additional tests. The same-source isolated suite now passes 9 tests.
- Native UI evidence: real pickup then same-WebView click produces DOM filenames plus retained IDs before the native completion promise resolves. Escape and right-click return false. The bounded driver cannot drag past its selected window bounds; cross-window target activation/overlap attempts did not produce independent receiver evidence. Handed the two live synthetic windows to root without claiming external reception.
- Replaced the initial PowerShell-hosted receiver with a standalone C# WinForms receiver. Hidden startup suppressed its window, so the interactive test executable is launched visibly; both label and form expose FileDrop. Old hidden test instances were terminated by their known owned PIDs. Removed the unused initial receiver script.
- Final isolated `cargo test --offline`: 9/9 passed. Clippy found only root's new `Sessions::new` missing `Default`; reported to root, without suppressing the warning. Root reports main-crate native/session/original resolver suite 13/13 passed. See README for exact acceptance boundaries and reproduction.
