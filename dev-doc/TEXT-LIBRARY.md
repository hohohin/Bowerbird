## 办公文档素材（2026-11-09）

- DOCX／XLSX／CSV 扩展原有 `texts` 类型，复用入库、连接目录、筛选、多选、右键和 3:4 卡片；预览仅返回最多 1200 字的阅读文字。`read_text_document(previewOnly:true)` 不向卡片传 DOCX 压缩包、不加载完整编辑器。导航结构与悬浮几何保持。
- DOCX 详情沿 `TextDocumentEditor`／Plate，复用已锁定的 `@platejs/docx-io` 导入／导出和 `documentCodec`。显示正文，不提供二进制源码编辑；保存通过 `save_docx_document` 验证 DOCX 包，复用原件版本核对、文件写锁、同目录临时文件原子替换和索引更新；`save_text_document` 明确拒绝覆盖办公格式。无修改不保存，冲突或失败保留草稿。支持正文、标题、基础格式、表格和嵌入图片的编辑器转换；分页、页眉页脚及复杂 Word 排版不保证无损，原生 Word 不是本应用的布局引擎。
- 表格用本机 `calamine 0.31.0`／`csv 1.4.0` 解析，`read_spreadsheet_document` 返回工作表名和二维字符串。保留空格、前导零、引号／分隔符／换行、空单元格和工作表内行列位置；CSV 支持 UTF-8 BOM、UTF-16 BOM 和中文 GB18030，按逗号分隔。XLSX 日期使用本机解析器的日期类型，数字为单元格值，不完整复刻 Excel 自定义格式、合并样式、图表或宏；公式不求值，有缓存则显示结果，否则保留公式文字。
- `SpreadsheetDocumentViewer` 使用同一素材详情容器，工作表标签和二维阅读表格；当前项目可添加所选工作表。`readFileContentCards` 共用文本／表格读取，文本生成文档卡，表格复用 `CanvasNotePayload`／`CanvasTextCard`，每张工作表独立建卡并保留标题；拖入、素材多选添加沿同一个冻结项目／落点及画板写入队列，部分写入失败重试不重复创建已完成卡片。首页添加到新项目仍沿原有“加入新项目素材库”语义。画板只存独立内容副本，不自动修改办公原件。
- 办公文件读取上限 20 MiB，压缩包累计展开上限 64 MiB；每张表最多 10000 格、工作簿最多 100 张表和 100000 格，超限明确拒绝，不截取后冒充完整卡片。包内 XML 仅本机读取、不解压到用户目录；巨型稀疏坐标在建立二维范围前拒绝。损坏／加密文件保留原件并提示重新另存；原 Markdown／TXT 继续使用 2 MiB、UTF-8 及原换行／BOM 保存契约。
- 验证入口：`core::text_documents`、`core::file_intake::tests`、`commands::media_import::tests`；`office-documents-ui.test.mjs`、`text-file-drop-ui.test.mjs`、`text-catalog-ui.test.mjs`、`text-library-ui.test.mjs`。使用合成 Office 包、临时数据库和隔离浏览器，覆盖导入筛选、正文预览、DOCX 编辑／真正 Word 包保存／重读／冲突、中文 CSV、多工作表、画板单元格／身份／重开／读取失败；截图和导出验证文件位于 `apps/desktop/.tmp/office-documents/`。需配套重建前后端，未发布安装包或验收真实用户 Office 文件、Windows 系统拖放及 Mac 原生。
- 本轮结果：上述原生 **35 项**、4 组界面回归、完整 TypeScript 与独立 Vite 构建通过；DOCX 嵌入图片往返检查同时核对生成包中的实际图片条目。原生测试仅向独立 EXE 副本添加 Windows 控件清单，未替换正式程序。前端产物在 `apps/desktop/.tmp/office-documents-build/`，原生日志在 `.tmp/office-{native,intake,upload}-tests.log`。

## 文本文件拖入（2026-11-08）

- `.txt/.md/.markdown` 沿 `FileDropImport`／`mediaImport` 接收，支持原路径和无路径 File、多文件、空文档及混合媒体。文件身份与收集箱规则沿用既有导入协议，保留原始字节；纯文本导入自动切到文本类型，混合导入切到全部类型，避免新文本被图片筛选隐藏。
- `prepareExplorerCanvasDrop` 共用冻结项目及落点的回调。文本通过 `textDocuments.read` 读取已登记原件，在落点创建 `note_type:"document"` 的 420×560 文档卡，沿画板写入队列持久化及重试；素材库内文本拖入也走同一放置入口，不重复导入文件。读取失败保留已入库原件，不创建空白卡片；接收期间离开项目仍保存到原项目，不向新画板插入。
- Markdown 正文保留，TXT 经 `textDocumentMarkdown` 复用 Plate 编解码转换为字面段落，`#`、`*`、HTML 等不误转成格式或执行内容。沿用 UTF-8、2 MiB 的读取边界。画板正文是独立文档副本，编辑不自动回写素材原件；原件仍从素材详情显式保存。工具栏的 `addMaterialAssets` 现有类型边界保持，本次接入拖放入口。
- `scripts/text-file-drop-ui.test.mjs` 使用正式画板、素材库与文件接收组件，覆盖路径／File、TXT／Markdown／空文档、3:4 正文、落点、重开、内部拖动、读取失败、切项目与混合筛选；原 `file-drop-ui.test.mjs` 回归通过。原生 `commands::media_import::tests`、`core::file_intake::tests`、`core::text_documents::tests` 共 17 项通过，验证 UTF-8 BOM／换行原样保留、临时文件清理及项目归属；TypeScript、独立 Vite 构建通过。均使用合成 IPC 或临时库，未修改用户库、未更新安装包，真实 Windows／Mac 系统拖放尚待原生验收。

## Markdown 写作交互（2026-11-05）

## 完整 Plate Demo 编辑器（2026-11-06）

本节替代上文基础工具栏／输入规则的实现细节及下文旧版语法限制。保留放大工作区、原文件详情、素材身份、保存冲突与生成草稿回填契约。

- 以官方 MIT EditorKit registry 为基础：标题、标记、颜色、字号、对齐／行高、列表／任务、链接、表格、分栏、提示块、折叠块、目录、代码、公式、脚注、日期、提及、表情、媒体、附件、代码绘图与 Excalidraw；斜杠、Markdown 输入规则、悬浮工具栏、块选择／拖动与撤销使用对应 kit。
- 底部空白点击：最后一块已有内容才新增正文空行；已有空尾行时只定位到该行。空文档、连续点击、标题、图片后续写与撤销／重开有交互回归。
- 评论、回复、解决状态、修订与 @提及按用户确认仅在本机文档使用，保存后恢复；无跨账号同步或多人实时协作。提及使用本地输入，不发送通知。
- Markdown 保持可读正文；无法由普通 Markdown 表达的格式、节点和讨论写入尾部 `bowerbird-document:1` 注释。读取核对正文指纹，外部修改正文后以新正文为准；损坏状态保留为字面源码。兼容 LF／CRLF，拒绝非法树、过深或超大状态。工作流投影和 Agent 输入剥离尾注，嵌套媒体仅在有效富状态下按已登记身份解析。
- 格式工具栏保持单行，窄屏横向滚动。所有 Plate 弹层保留独立主题作用域，背景不透明；字号输入离焦不抢占下一个菜单，Esc 可关闭。
- 固定和浮动工具栏使用同一插件变换；修复字号输入丢选区、表格合并后无法拆分、评论首次插入导致 Slate 节点身份变化、块操作后的隐式多选、滚动浮层位置和键盘导航。
- 工具栏 Agent 使用既有 Codex CLI／Cloud DSH 及模型／积分菜单，可生成、改写、评论和改写所选表格；接受／舍弃作用于真实正文。请求期间手工编辑过目标时只保留回复预览；表格返回尺寸不匹配不改原表。取消失败可再次停止，读取失败取回原请求。Cloud 账号门控与计费链路保持不变。
- 图片／音视频上传复用应用媒体导入；浏览器选择器的相对 `File.path` 不冒充本机原路径。附件使用内容哈希命名、原子写入、路径边界校验与 50 MiB 上限，同内容复用、不覆盖。原生命令为 `save_document_attachment` / `resolve_document_attachment`，需重编译桌面端后可用。
- 按用户反馈移除 Markdown / HTML / Word 文档导入，保留 Markdown / HTML / PNG / PDF / Word 导出；HTML／图片／PDF 使用静态文档渲染，嵌入可读取的媒体和公式字体，绘图导出图像。Word 导出会受目标格式能力限制；富编辑器状态的完整恢复以应用保存的 Markdown 为准。
- 显式粘贴或插入的外部媒体链接可显示并保留 URL，不冒充素材库身份。未知 HTML／MDX／frontmatter 仍不执行，源码语法保留为原文块。Mermaid / Graphviz / Flowchart 本地渲染；PlantUML 只有点击“在线预览”后才发送图表源码。Excalidraw 运行字体本地化。

正式入口为 `TextPlateEditor.tsx` 和 `components/text-editor/plate/`。旧 `TextBlockActions`、`TextBlockType`、`TextFormatToolbar`、`TextInputRules` 已被官方 kit 替代并删除。来源与适配说明见该目录 README，测试矩阵及质量工具边界见 [本轮日志](../project_logs/2026-11-06-text-editor-demo.md)。未发布安装包，未调用真实付费模型，Mac 原生、超大文档长期性能及跨设备恢复不在本轮验收范围。

## 最近文档与自动保存（2026-11-06）

- 放大文本工作区标题旁提供“最近”，显示文档名称和最近访问／编辑时间，当前文档有勾选。默认加载 50 篇，“显示更多”继续读取；不会自动删除较早文档。沿用 Plate 的不透明菜单、键盘导航和工作区 portal，窄屏不越界。
- 工作区文档通过 `recentTextDocuments.ts` 保存在当前桌面 WebView 资料目录的 IndexedDB（`bowerbird.text-documents`），不上传云端。保存完整 Markdown 与既有富状态尾注，标题、块格式、讨论和媒体引用不另做降级转换。独立于素材原件和项目卡片；保存到集合／项目仍是显式动作。
- `TextDocumentAutosave` 合并 300ms 内的输入、串行提交；事务完成后才显示已保存。关闭、切换文档和添加到生成框前冲刷最新输入；后台／卸载时尝试冲刷。写入失败保留内存草稿、显示重试并阻止直接关闭；首次读取失败时暂不开启编辑，避免初始化整理写入临时内容；可重试读取旧草稿或返回。关闭整个浏览器进程后可恢复已提交的数据，不承诺强制杀进程或断电时尚未提交的最后输入。
- 生成入口使用原草稿指纹查回对应文档；生成框变化后创建／恢复另一篇，旧文档仍在“最近”。既有 sessionStorage 草稿兼容读取，后续只在内存保留生成框转换关系，持久内容统一交给文档库。
- 画板入口提供稳定来源与正文指纹，沿已有原卡片写入队列保存。切换到其他最近文档时，通过 `isSourceDocument` 区分当前文档与宿主卡片；编辑、返回或添加到生成框不会误写当前卡片。每次换文档重新创建 Plate 实例，撤销和段落 Agent 不跨文档。
- 文档 revision 在读写事务内校验；旧窗口不能覆盖新窗口已保存的内容，冲突时保留编辑区并提供“另存草稿”，独立保存当前内容后可正常退出，原较新版本保留。保存期间继续输入会提交最新内容，添加到生成框时发现快照已过期则保留编辑器供重新添加。
- 隔离验证覆盖浏览器进程重启、富文本／图片引用、存储读写失败和重试、跨窗口冲突、较早文档分页、深浅主题／窄屏，以及真实创作框／画板来源隔离。原文件详情仍沿版本校验显式保存，不自动覆盖已连接文件。Mac 原生及实际桌面进程异常退出不在本次隔离浏览器验收内。

实现与完整验证见 [本轮日志](../project_logs/2026-11-06-text-recents.md)。

## 文档内 Agent（2026-11-03）

- 放大工作区只在光标所在段落的把手左侧显示 Agent。点击气泡外部自动关闭，保留点击目标的焦点；气泡内部及其模型菜单不触发关闭。关闭沿既有任务取消与迟到结果保护。气泡复用 `ModelSelect` 的 Provider／自有额度／Bcoin 菜单，嵌入菜单使用工作区的浮层与焦点边界。
- 本机沿用 `agent_ds_workflow_start` 的 Codex CLI 通道，每次请求使用隔离会话，仅显式传入当前段落和本气泡历史。Cloud 沿用统一 DSH 的 `textRewrite`／`text.result` 契约，关联真实项目与新建创作线程；无项目时沿用素材库创作项目准备入口。没有新增 runner，也没有使用 DeepSeek 普通聊天代替 DSH。Cloud DSH 仍限服务端授权的测试账号，BYO／并发策略保持。
- 回写接口为任务结果中的 Markdown 文本，使用 Plate 变换插入发起段落之后，连续对话从上一轮插入末段继续。输出可撤销；以节点 ID 和发送快照校验锚点，段落改动或删除时保留回复，并提供“插入到光标处”，不覆盖手工内容。当前正文＋气泡历史沿既有 16000 字输入上限，回复亦为 16000 字上限；不额外传全文或素材原件。
- 读取异常保留原请求“继续取回”，不重复提交；停止、关闭气泡、切换到另一段落气泡、关闭工作区都会使迟到结果失效并尝试取消。取消失败保留可见提示。气泡历史为当前打开期间的会话状态，关闭后新开；已写入正文按原草稿／保存流程持久化。
- `text-agent-ui.test.mjs` 覆盖两通道、额度菜单、连续对话、Markdown／撤销、并发修改／删除、错误请求身份、失败／非文本 Cloud 结果、原请求取回、停止与关闭竞态、账号变化；布局、段落操作与原文本详情回归、TypeScript 和独立 Vite 构建通过。使用合成 IPC，无真实模型调用／扣费；Cloud 服务和本机 CLI 的真实运行验收未纳入。本轮行动与质量证据见 [日志](../project_logs/2026-11-03-text-agent.md)。

## 接入范围

- `.md`、`.markdown`、`.txt` 复用「建立连接」及文件夹扫描，登记原路径，不复制已有文件。
- 现有素材库类型控件增加文本，沿用全部、标签、集合、搜索、分页和分栏。卡片按需读取正文片段（见上方卡片契约），打开详情才加载 Plate。
- 编辑器在原 `AssetDetail` 媒体舞台内，原顶部栏、侧栏和右侧资料区不改布局。文本不显示图像反推／再创作，也不能作为画板图片或模型图片参考。
- Markdown 有正文／源码、标题、粗体、斜体、简单列表、引用、撤销／重做；TXT 按字面编辑。显式保存或 Ctrl/⌘+S 写回原文件。
- 文档内可插入已有图片、音频、视频引用；移除文档中的块只修改文档。原素材详情的转发入口仍未新增；本次创作框／画板入口见上节。

## 原件与草稿

入口：`core/text_documents.rs`、`commands/text_documents.rs`、`TextDocumentEditor.tsx`。

`read_text_document(assetId)` 和 `save_text_document(assetId, expectedVersion, text)` 返回 `{ assetId, path, text, version, format }`。命令只接受登记的素材身份，读取 `assets.store_path`，不提供任意路径写入。磁盘工作在线程池执行。

- 暂支持最多 2 MiB 的 UTF-8（含 BOM），其他编码、二进制、只读、失联或超大文件清晰报错。
- 版本为文件内容 SHA-256。保存先核对打开版本，同一路径的应用内保存串行；准备替换文件后再次核对版本及登记路径，发现外部变化拒绝覆盖。
- 在原目录写临时文件并同步后原子替换，再刷新原素材索引、广播更新；标签和身份保持。索引刷新失败明确区分「原件已保存，索引待刷新」。没有与任意外部进程协作的文件事务，不宣称能消除校验和替换之间的所有系统级竞争。
- 保留 UTF-8 BOM、常规 LF/CRLF、系统基本权限；无变化保存不改混合换行。编辑后混合换行按原件是否含 CRLF 统一。未验证扩展 ACL、扩展属性或网络文件系统替换语义。
- 草稿以素材 ID 和原路径分开保存在当前应用会话的内存及 sessionStorage；内存是存储失败后的兜底，并显示先保存再退出提示。应用退出尝试提示未保存，不承诺进程崩溃／彻底退出后恢复。
- 保存回包合并共享最新草稿，保存期间继续输入、离开再打开和旧回包乱序均不会覆盖新输入。重新读取原件丢弃未保存草稿前确认；读取期间已继续编辑则忽略旧读取回包。

## Markdown 与媒体

使用 MIT 的 Plate 53.5.2 与所选基础、列表、Markdown、媒体插件，不使用 Plate Plus 模板。锁定版本见 `apps/desktop/package.json` 与根锁文件；许可文本随 `apps/desktop/public/licenses/text-editor.txt` 进入前端构建产物。

媒体保存为受控引用，例如：

```html
<img data-bowerbird-asset="ID" data-caption="URL编码说明" data-source="URL编码原路径" />
```

`audio`、`video` 使用同一属性协议。原路径是溯源信息；当前仅解析已经登记的 ID，不依据文档内容自动读取或登记任意本机路径。文件导入通过现有原位连接 API，图片按需显示、音频复用共享波形播放器、视频 `preload="none"`。当前同库重新打开可恢复引用，不宣称跨设备 ID 恢复已完成。

当前语法与外部媒体行为以上方“完整 Plate Demo 编辑器”为准。正文编辑可能规范化 Markdown 的空行、强调符号与软换行空白，不宣称字节级无损；仅打开或切模式不会自动写原件。
