# 2026-11-06 快传本机发送

用户要求快传支持从本机向其他终端发送文件，沿既有无需安装App的浏览器方式交付。当前决策见 PROJECT.md，本记录不代表安装包已发布。

## 行动与原因

1. 读 ub-mode、UI/UX 技能、当前项目／快传／文件契约／复用地图／UI／错误说明；核对工作区已有无关编辑，所有测试使用临时数据。轻量 memory registry 查询无相关命中。
2. 查到 vendored LocalSend 已有 WebSendConfig 和浏览器下载事件；复用协议、Host/Origin边界、配对码、二维码、单调快照、文件选择器和面板，避免新增服务器依赖或云中继。新增 send.rs 只负责所选原件与流生命周期。
3. 首写真实 HTTP 回归。沙箱套接字被系统拒绝不计红灯；正常权限重跑得到预期 404 != 200（原接收allowlist），证据 `.tmp/quick-transfer-send/red.log`。随后按收发模式划分路由。发送文件名和大小仅在配对后可见，随机ticket绑定IP，路径只留本机。
4. 发送与接收独立开关和监听；原接收开始更新快照时保留发送状态。关闭发送等待连接／文件任务释放，收起和切页继续。选择1–100项，单件2 GiB、集合10 GiB，去重规范路径；发送前核对原件大小／修改时间。流每块256 KiB、队列2块、最多4流，60秒读写超时，避免整文件进入内存。不同设备可重复下载，没有累计下载流量限额。
5. 正式面板新增接收／发送页签，复用字体／色彩／滚动／二维码。新增系统多选、移除、开启和关闭；目录不用入库。终端提供配对与逐文件下载，使用浏览器原生下载而非Blob整份缓存，不把点击下载当成对端保存成功。中断后禁用旧链接并可重连，静态页面不泄露原件路径。
6. 修复LocalSend原下载session ID为IP的可猜测问题，改UUID；重新配对撤销该IP旧ticket，最多200会话。探活只带ticket，避免自动配对反复互踢；保留三次PIN错误封禁。中文文件名补filename*；逆向旧patch重建上游，以UPSTREAM.json中的CRLF字节哈希核实，再生成完整BOWERBIRD.patch。LICENSE与安装资源配置保持。
7. UI初次测试因独立Vite配置导航超时，不计预期功能失败；切回已有项目配置。窄屏初次断言测到全应用既有760px最小宽度，改查实际快传面板内容边界，未更改全局布局。检查深浅色桌面及320px接收端截图。
8. 官方 crapper／dryer／mutator 首次直接运行受grammar下载DNS阻断；复用已有本地官方TS/TSX grammar适配器后均成功，未修改算法。dryer阈值0.8无重复。无覆盖率输入，CRAP=N/A，不声称CRAP<10已达标；报告包含现有面板组合条件，CC最高24。隔离变异将移除条件 `!==` 改 `===`：基线通过，真实IPC文件列表断言发现错误文件，变异被杀死，无超时；初次中文日志GBK解码失败后用UTF-8重跑确认。生产源码未参与变异。

## 边界

未访问用户库、安装／重启应用、构建或发布安装包。真实Android/iOS下载保存位置、无线AP隔离／防火墙、Mac原生待实机验收。HTTP只用于可信局域网；发送过程中原件不冻结，应避免编辑。浏览器接管后的保存完成无法从页面可靠确认，桌面不显示虚构“对端已保存”。本轮实现是浏览器拉取所选原件，不包含设备自动发现或推送到对方LocalSend App。
