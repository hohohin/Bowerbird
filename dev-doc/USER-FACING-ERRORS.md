# 用户错误提示审计与验证

日期：2026-10-24。当前为本地源码修复，尚未发布客户端或部署官网。项目决策以 [PROJECT.md](../PROJECT.md) 为准。

## 检查方法与范围

对桌面 `src`、原生 `src-tauri/src`、浏览器扩展和官网进行错误出口检索，再沿「异常来源 → 状态保存 → 正文／提示／通知」追踪。检查覆盖当前 145 个桌面 TSX 文件，包含普通页面、截图独立窗口、任务详情与开发入口；原生搜索覆盖 140 个 Rust 文件及注入脚本。不能将检索命中数等同于真实故障场景全部经过实机验证。

| 范围 | 已处理的展示出口 |
|---|---|
| 全局通知 | `notifyError`、直接 `notify(..., "error")`、直接派发通知事件，发出与接收处均有中文兜底 |
| 素材与项目 | 分页列表、批量删除、项目删除／重命名、集合、画板设置、卡片命名 |
| 本机文件 | 文件浏览、迁移、随图资料恢复、导入失败列表、图片标注、截图、视频播放／截帧 |
| 分类与理解 | 分类状态及历史错误、标签来源、反推失败、视觉规范提炼、侧栏任务失败 |
| 生成与工作流 | 历史错误、运行期间的命令输出、工作流步骤错误／说明、模型不可用提示、图层任务、视频复刻 |
| Agent | 工具失败事件、保存结果失败、任务恢复说明、未知事件／状态码、停止结果尚未确认的提示 |
| 设置与安装 | 账号及兑换、Codex／即梦安装授权、快捷键、H3 环境检查、更新检查／下载／安装／重启 |
| 浏览器与官网 | 内置浏览器、网页采集反馈、官网双版本登录／生成、微信回调、后台操作错误 |

正文、悬停 `title` 和辅助说明同时检查。最终交叉复核额外修复了批量删除 `failedNotice` 别名；没有只根据字段名 `error` 判断覆盖范围。

## 转换规则

桌面入口为 `apps/desktop/src/lib/userError.ts`。优先保留已经清晰且带操作指引的中文，支持必要产品名、快捷键与文件格式；已知异常给出明确恢复方向：快捷键占用、权限不足、磁盘不足、文件丢失／占用、资料库忙／无法读取、登录失效、积分不足、内容审核、限流和网络故障。

未知英文、混合技术异常、路径、URL、内部代码、结构化响应、堆栈和过长内容使用调用位置的中文兜底。兜底文案本身也经过检查，避免模板拼接把原始异常重新带回界面。安全中文允许保留磁盘容量／缺口等有用信息。

超时或丢失响应不代表生成失败。公共网络提示提醒查看原任务状态、不要重复提交；停止失败仍说明尚未确认停止，既有查询、恢复、重试与计费逻辑保持。

官网 `website/user-error.js` 使用单独的已审核文案表与状态映射，不回显微信 URL 错误参数、上游响应或部署配置。邮件及回调正确处理服务返回的 `{ error }`，不再显示成功。

## 保留的诊断与边界

- Rust `AppError` 的序列化、IPC、任务错误、数据库历史、运行时重试判断保持原值；转换发生在展示边界，避免破坏错误分类、恢复或模型反馈。
- 原生日志、明确查询／复制／导出的诊断仍保留。用户创作内容、Agent 正常回复、素材名称、正常文件路径展示不作为错误过滤。
- 分类原始响应与阶段诊断仅开发模式可见。生产任务的专用诊断查询／复制入口仍供定位问题使用。
- 原生直接错误弹窗仅发现截图快捷键路径，已使用固定中文并记录原始错误；原生启动 `expect` 属于诊断输出，未作为普通提示展示。扩展内部错误最终映射为固定“采集失败”，本轮未修改协议。
- 官网下载为静态链接，没有网页支付界面；服务器与账号网关的协议错误继续由各自客户端处理，未改写后端接口。
- Windows 的准备脚本从当前源码镜像构建，`Windows/overrides` 只剩说明文件；macOS 没有前端源码覆盖步骤。源码修复仍需重新构建安装包，跳过构建而复用旧产物不会包含这些变更。
