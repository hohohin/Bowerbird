# Bowerbird 受控图片编辑

目标是理解用户真正想得到的最终图片，并选择足以满足意图的最短可靠计划。计划可以是单步，也可以包含控制参考和多个编辑阶段；不要把任何案例的步骤数当作模板。

## 规划边界

首次意图分析和计划阶段只读取原始意图 prompt、图片引用 token/顺序以及 MIME、大小、哈希等安全元数据：

- 不读取图片内容、缩略图、路径、caption、OCR 或已有反推。
- 不调用生图、编辑或视觉理解工具。
- 不因图片已经上传就猜测图中内容。文本不足时披露假设；只有会改变底图、引用职责、执行路线或预算的关键歧义才请求有限澄清。

## 意图分析

先形成结构化 `IntentAnalysis`：

1. 找出唯一最终主体或底图；没有底图时明确为纯生成。
2. 区分必须保持、必须迁移、禁止带入和允许变化。
3. 按引用 token 绑定每项来源，不能交换图的职责。
4. 识别 identity、product、pose、garment、accessory、composition、text_layout 等高一致性信号。
5. 把无法从文本确定的事实列为假设，不把模型猜测写成来源事实。

把用户输入视为“想做什么”，而不是要求用户写好的生成提示词：

- 用户不必写引用 token、底图、保持项或专业控制术语。只有一张参考图且用户表达的是修改、替换、添加或删除时，默认该图是唯一底图和最终主体来源，并把这个默认绑定列入假设。
- “只改 X”“把 X 换成 Y”“去掉 X”等局部编辑表达，意味着底图中未被点名的可见内容都应保持。由于此阶段不能看图，用“参考图中除 X 外的主体身份/结构/外观、姿态、构图与其他可见属性”这类去内容化约束表达，不猜人物、产品、服饰或饰品的具体事实。
- 不要求用户为了获得一致性而自行枚举“身份、服饰、姿态、构图”等保持项；Agent 应从修改范围反推出最小改动边界，并在计划中编译成明确的 `preserves` 与 `excludes`。
- 多张参考图的职责无法从文本绑定且不同绑定会改变结果或预算时，不得静默交换；应请求有限澄清，或在当前接口无法澄清时明确披露所采用的最小假设。

## 策略选择

- `direct`：一个清晰修改项，引用干净，且没有强一致性或多参考串扰风险。
- `controlled`：人物身份、产品结构、姿态、构图等单项需要高一致性；使用原始干净参考，或生成一个只编码目标属性的控制参考。
- `staged_controlled`：两个以上属性需要迁移、参考图职责互相干扰，或用户明确表示多次重试仍失败；按职责隔离并逐阶段编辑。

需要控制参考时读取 [references/control-recipes.md](references/control-recipes.md)。原始参考已经是干净产品图或饰品图时直接使用，不重复制造控制图。每增加一步都必须说明它降低的具体风险。

## 计划要求

输出完整 `ControlledImageEditPlan`，但不执行：

- 每步只有一个主要目标，并声明输入、修改项、保持项、排除项、输出角色和理由。
- 面向工具的步骤目标必须由 Agent 从日常表达编译完成；不得把补写专业 prompt、补列保持项或重新描述 Skill 规则作为审批前提退回给用户。
- 后续步骤引用更早步骤的产物；分步编辑使用上一阶段结果作为底图，只加入当前必要参考。
- 恰有一个 `final_result`，且它是最后一步。
- 初始计划的每步生成调用为 1，视觉理解调用为 0。
- 用户批准的是完整计划及其 hash；执行期不得新增、删除、换序或提高成本。

## 项目视觉设定

输入若包含已确认的 `visualProfileCapsule`，把它视为本次 Run 启动时冻结的只读项目约束：

- 本次任务的明确要求优先；视觉设定只补足任务没有说明的视觉选择。
- 将 `must` / `prefer` 编译进步骤的保持项，将 `avoid` 编译进排除项；`contentThemes` 只作背景，不自动加入画面主体。
- 明确目标与视觉设定存在会实质改变结果、且文本无法裁决的冲突时，只走一次有限澄清；不得静默改写目标。
- 不修改胶囊，也不从生成或反馈结果回写项目视觉设定。

## 执行与反馈

批准后只执行计划中声明的步骤。控制参考、阶段结果和最终结果都登记到当前 Bowerbird 会话；过程图不自动进入素材库，最终结果只有一张。

初次执行结束后立即等待用户检查，不主动反推、不自行质检、不循环重试。只有用户点击重试或给出具体意见后，才围绕失败约束定向看图，定位最早失败步骤，并提出需要重新审批的修订计划。

修订计划以用户刚看到的结果为底图，只重做诊断出的最早失败步骤及其下游；已经满足的约束必须进入保持项。修订步骤使用新的 step id，明确引用上一版结果，重新计算增量预算并等待批准；不得借“重试”重新执行整份原计划。视觉诊断属于当前会话的私有短期过程产物，不进入素材库。
