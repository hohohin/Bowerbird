## 3. 应接收的共享功能

### 3.1 工作流容器、预览和模板 v3 布局

- 画板右键可独立「封装为容器」；解封只去除容器框，保留原卡片、连线与内容。容器沿原生 section 保存 `workflow_container: true` 和固定 `member_ids`，不新增执行节点，不按几何位置吸收其他卡片。
- 保存/封装确认面板按原相对位置和尺寸显示预览，支持滚动、缩放和适应选区。复选框决定容器成员；模板仍保存整个选区。封装若会包住未选卡片，选中成员整体移到右侧空位，保持相对布局。
- `.bbworkflow.json` 新写 schema **v3**，兼容读取 v1/v2。`layout` 白名单保存相对位置、尺寸、公开输入对应关系及 `enclosed`；恢复原生内容卡、未连接内容卡和容器。携带素材/文本仍为显式选项，禁止携带私有路径、账号/会话/任务身份及 provider 配置。
- Rust `workflow_encapsulate` 在同一事务中保存容器、几何、工作流 revision 和可选模板；失败整体回滚。运行中的图拒绝封装；复用时若容器创建失败，可续做封装，避免重复创建流程卡。
- 容器不折叠、不嵌套。模板的循环、本机 Agent 通道等既有便携限制没有因此消失；视频卡也明确禁止模板/数据包导出。

必须一起接收：`CanvasWorkspace.tsx`、`SaveWorkflowTemplateDialog.tsx`、`WorkflowTemplateLibrary.tsx`、新增 `WorkflowTemplatePreview.tsx` / `workflowTemplatePreview.ts`、`workflowTemplates.ts`、`workflowTemplateContent.ts`、`canvasNotes.ts`、`canvasWorkflowRuntime.ts`、`api.ts`、`commands/workflow_templates.rs`、`src/lib.rs` 的命令注册及 CSS。仅复制前端会缺少封装 IPC；仅复制后端会留下 v2/v3 校验和布局不一致。

### 3.2 正式版 Agent 图文输出与 Codex CLI

- 正式构建显示「本机 Agent DS · 图文处理」「Codex CLI · 图文处理」「Cloud DSH · 文本改写」。本机两项支持文字、表格、图片和混合输出；Cloud 保留文本契约。
- 选择器、输入解析、图片输出口和执行分支均解除 DEV 限制。Rust 正式提交复用 `require_byo`，只开放工作流 `purpose=agent-text`；旧开发聊天、规划及规划反馈继续受原限制。
- 结果查询、取消、生图桥接和图片入库支持原请求恢复。每卡独立会话、循环每项隔离、冻结通道/默认生图 provider、先持久化任务身份和未知状态不重发继续保留。
- release 请求根从打包机源码目录改为应用数据目录。Mac 对应 `~/Library/Application Support/com.bowerbird.desktop/.agent-z/`，投递位于 `ds-inbox/`，DSH cwd 为 `workspace/`，登录链接为 `dsh-web-auth-url.txt`。debug 仍用仓库 `.agent-z`。Mac 需要在安装后的 release 包验证含空格路径、读写权限及 DSH 会话 cwd 匹配。
- DSH 服务由用户启动，安装包不附带 DSH 服务或登录资料。Codex 继续使用 Bowerbird 私有认证配置；不迁移另一台机器的 Cookie、登录链接、队列或历史会话目录。

核心差异在 `CanvasWorkflowLayer.tsx`、`canvasWorkflow.ts`、`canvasWorkflowRuntime.ts`、`commands/agent_ds.rs`、`commands/codex.rs`。`commands/agent_ds/codex.rs` 还增加了 Windows 原生假 CLI 夹具，Unix 夹具保留。

这些 release 改动是**共享源码逻辑，没有仅限 Windows 的平台条件**。Mac 合入后会得到相同正式版路径与开放行为，应按最新 `PROJECT.md` 范围验收；不能照抄历史文档中「保持 DEV/debug」的描述把限制加回。当前线上 Mac 801 的旧行为仍由旧安装包决定。

### 3.3 生成卡片新增视频模式

- 参数栏新增图片/视频切换，复用已有即梦/方舟渠道和四模式控件。图片 provider/比例与视频参数分别保存，切换、复制、重载后保留。
- `WorkflowNode.generation` 保存媒体类型和视频设置。参考素材按正文 `@` 顺序提交；首尾帧顺序不能按连线或素材库顺序重排。视频模式可接合法视频参考，非法输入在创建任务身份/提交前拒绝。
- 执行继续复用普通生成、入库和 job/turn 恢复链路；重载取原任务，不重新提交。内容卡可接视频，静态图片专用卡拒绝视频输入。
- 输出在界面标为「视频」，持久化端口 ID/type 仍为 `image`，用于兼容已有素材连线；不要单独改成新的 `video` 端口造成断线。
- 输入和历史使用静态封面，主动打开才播放。视频卡可复制；模板/数据包暂未携带视频参数，保存/导出明确拒绝，不能静默降成图片卡。

核心文件：`CanvasWorkflowLayer.tsx`、`CanvasWorkflow.css`、`WorkflowGenerationHistory.tsx`、`canvasWorkflow.ts`、`canvasWorkflowRuntime.ts`、`workflowTemplates.ts`；新增回归 `scripts/canvas-workflow-video.test.mjs`。没有新增云端能力、迁移或计费规则，详见 [工作流视频契约](../dev-doc/CANVAS-WORKFLOW.md)。

### 3.4 即梦视频查询临时超时恢复

`src-tauri/src/codex/jimeng_video.rs` 的查询轮询按同一个 `submit_id` 继续查询，临时传输错误间隔 10 秒，连续最多额外重试 3 次；得到有效响应后清零连续次数。仅识别命令层 deadline/client/I/O/TLS 超时、连接重置与应用单次命令超时。

提交不重试；远端明确 fail（原因含 timeout 也一样）、登录错误、解析错误与未知状态不走传输重试。耗尽提示保留任务编号、稍后取回原任务；取消可打断等待，失败清理本次下载临时目录。不要把“查询超时”改成“远端生成失败”，也不要通过重提生成恢复。假 CLI 更新位于 `src-tauri/tests/fixtures/dreamina-video-cli.rs`；契约见 [Seedance 集成](../dev-doc/SEEDANCE-2.5-INTEGRATION.md)。
