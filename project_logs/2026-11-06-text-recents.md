# 最近文档与自动保存

用户要求在文本编辑器内查看最近文档，并在退出后保留编辑内容。本次仅接入放大文本工作区；原件编辑继续使用已有版本校验和显式保存。

## 实施记录

1. 阅读 `PROJECT.md`、开发计划／复用地图、文本专项、UI 规范及错误展示约定，按 `ub-mode` 与 `ui-ux-pro-max` 执行。核对现有 `useTextWorkspace` 的 sessionStorage 草稿、`TextWorkspace`、Plate dropdown、文档编解码及画板写入队列：旧入口只能恢复同一生成草稿，来源变化后旧稿没有列表入口，无法满足跨重启恢复。
2. 先编写关闭／重开、来源变化及最近文档切换的隔离浏览器测试，观察旧实现恢复失败，再接入独立本机文档库。选择当前 WebView 资料目录的 IndexedDB，不新增后端、原生迁移或云端同步。完整 Markdown 和既有富状态尾注沿原编解码保存，不复制 Plate 编辑模型。
3. 新增 `recentTextDocuments` 管理文档 ID、来源指纹、访问时间、最近分页及事务内 revision 校验；新增 `TextDocumentAutosave` 合并 300ms 输入并串行写入。保存提示以事务完成为准，退出／切换／添加前等待最新内容写完，写入期间的新输入不被旧结果覆盖。
4. 标题旁接入“最近”和小型保存状态，复用 Plate 菜单、工作区 portal 与主题。默认显示 50 篇，继续加载旧文档，不自动清除历史；不增加工具栏行。调整菜单选择器优先级，避免上游工具类盖过最大高度。
5. `useRecentTextDocument` 管理恢复、切换、失败重试和来源绑定。画板只把来源文档送回原卡片，其他最近文档不会误写宿主；切换时重新创建 Plate 实例，隔离撤销及 Agent 会话。生成框仍沿原转换和过期快照保护。
6. 注入写入失败、首次读取失败、延迟事务完成和双窗口编辑，逐项验证内容保留。补充首次读取失败复现：临时编辑器的初始化整理可能触发写入并干扰恢复，因此读取成功前不开放正文编辑，失败可重试或返回；已有文档的正常退出须先成功保存；多窗口冲突提供“另存草稿”，保留双方内容；添加期间又输入时拒绝发送旧快照。
7. 检查素材库导航回调、原件保存和现有入口，没有改造公共导航协议。界面外卸载采用尽力冲刷；保存失败时的显式返回／Escape、切换、添加保护由工作区负责。
8. 在隔离副本运行质量工具。修正工具在 Windows 上的进程树清理兼容，结束本次失败超时遗留的明确 PID 树，再完成变异测试。没有修改生产工具依赖、其他任务进程或用户资料。
9. 更新文本专项、复用地图及 `PROJECT.md` 的当前约定。只暂存本次代码与文档；画板及共享文档使用索引原件生成局部补丁，保留工作区其他任务的修改。

## 范围与限制

自动保存留在当前设备的应用资料目录，集合／项目输出仍需点击对应保存按钮，不修改已连接原文件。已提交内容经完整浏览器进程重启验证；强制终止进程或断电时尚未提交的最后输入不作保证。没有发布安装包，没有调用付费模型或使用真实用户库；Mac 原生与实际桌面进程异常退出尚未实机验收。
