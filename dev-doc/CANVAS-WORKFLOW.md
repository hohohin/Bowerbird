# 画板工作流实现与验收

产品范围以 `PROJECT.md`「画板工作流」约定为准。本文记录首版实现契约，不代表安装包或线上发布。

## 操作

1. 左侧工具栏新增指令、生成、技能卡片；拖动卡片标题移动位置。
2. 从素材栏拖图片到卡片，或悬浮画板图片后从右侧圆点连接图片输入。文本卡每个单元格悬浮时显示文本输出端口，读取该单元格当前内容；插入/删除行列使用稳定单元格身份，删除已连接单元格会明确报错，不重绑其他格。紫色为文本，绿色为图片；右键输入端口或点击来源标签可断开。
3. 指令卡选择反推、复用生成提示词、分层编辑，均可点击「运行此卡片」独立执行，无需发条。反推固定提供聚合「提示词」输出，完成后另展开各维度端口。复用输出完整生成提示词与当次参考图片。分层运行直接执行「开始拆分」（空要求、auto 尺寸），不打开面板；结果完整保存后更新原图 Layers 角标，并从「产物」及各层端口输出素材、继续下游。用户从原图右键「分层编辑」进入工程。
4. 生成卡有文本输入、图片输入和本地指令。上游文本按连接顺序拼接，再追加本地指令；悬浮栏配置模型与比例。输出为独立「会话」类型，自动连接对应生成会话卡片，不能冒充图片输入；需要图片时从会话结果图片连接。旧生成卡图片连线保留为明确失效连接，运行提示重新连接。
5. 技能首版接图片创作、HTML 图文排版两种既有方法，通过统一 Agent 调用，端口显示图片或排版截图。沿用测试账号、技能 allowlist、并发和服务端计费门控。执行详情内处理审批，成功后在卡片点继续取回整组图片。
6. 发条只标记流程起点：点击工具栏发条，再点击卡片吸附；点击发条运行该起点及其下游，拖到其他卡片移动起点，右键取下。各卡片的「运行此卡片」只执行本卡，其他上游须有有效结果。
7. 画板文件夹右侧在悬浮时显示图片输出端口，支持连接视觉规范、生成及多图反推的图片输入；展开/折叠时跟随文件夹边缘。绑定文件夹身份，每次启动读取当前成员、按成员顺序去重并排除视频，将图片列表保存为本次固定输入；期间修改成员只影响下次运行。空文件夹或已删除文件夹在提交任务前报错。单图指令仍限制一张输入。

文件夹端口验收（2026-09-21，源码未发布）：Chromium 覆盖 hover、连接视觉规范、重载、展开落点、成员顺序/更新/运行冻结、空组及删除阻断；原工作流与视觉规范模拟回归、Rust 工作流 4 项、类型检查和生产构建通过。未调用真实模型或发布安装包。

## 数据和执行

### 文本卡内容输入（2026-09-22，源码未发布）

- 整体与每个单元格均有悬浮输入端口，接收文本或图片；整体连接在第一列新增一行，同一连接重跑更新该行，单元格连接替换该格。文本保留原始空白、换行和制表符；图片写入 `@图片N` 索引和素材身份，显示缩略图索引并复用对话框的悬浮预览。删去索引后不再传递对应图片。
- 文本输入作为工作流内部 `text` 步骤保存，绑定原生 note/cell 稳定 ID，不另画一张工作流卡。已有结果或静态来源连接后立即写入，不启动下游模型；流程运行时等待上游、写入后推动下游。单元格文本输出携带图片引用，生成前统一图片序号；外部单元格正文与引用一同冻结。循环拒绝、目标删除预检、同表写入互斥、右键断线保留内容和下游连接。
- 验证：隔离 Chromium 覆盖整体新增/重跑、原文替换、图片身份传给生成、上游→单元格执行、循环拒绝、重载、点击连线与右键断开；既有工作流 UI/执行回归、Rust 目标依赖校验与 note 引用持久化、类型检查/生产构建通过。未调用真实付费模型或发布安装包。

文字结果卡输入可断开（2026-09-21；09-22 统一为整体输入端口）：悬浮原生文本结果卡时左侧显示紫色输入点，右键断开其反推来源。保留文本和单元格下游连接，移除执行依赖并清理下游旧缓存；运行中禁用。重载不恢复连接，来源重跑另建结果卡，不覆盖已断开的文本。浏览器覆盖右键、内容保留、重载及重跑隔离，类型检查/构建通过。

### 分层图片产物文件夹与去重（2026-09-21，源码未发布）

- 分层卡导出的图片在画板创建「分层产物」文件夹，并从产物端口连到文件夹；后续反推继续读取这些图片。文件夹/成员使用稳定身份，重跑复用，用户移动文件夹后保留位置。工程修改产生的新版本保留在同一文件夹。
- 工作流专用导出以原图 ID 与完整导出工程内容的 SHA-256 作为复用键，在本地 analyses 保存产物索引；串行保护并发查找/创建，重跑复用仍存在的文件。新产物 `library_hidden=true`，只在画板显示；手动面板合成导出维持原行为。命名使用原图名与图层名。既有重复图片不自动删除，也不修改用户已加入中央库的素材。
- 原生测试覆盖重复导出同 ID/数量不增长、隐藏标志、工程改变新版本、手动导出独立；模拟链路覆盖画板文件夹及重跑成员不重复。Rust 分层 4 项、模拟运行、类型检查及生产构建通过。涉及 Rust 后端，需重启更新后的桌面程序；未发布或真实调用云模型。

### 分层复用与结果文本中继（2026-09-21，源码未发布）

- 视觉规范旧云兼容：纯图片卡片使用已部署的 schema 1 图片提炼协议，不调用 `capabilities`；只有非空文字要求才在图片观察前检查 schema 2 支持，并发送 requirements。旧服务返回「未知 action」时明确提示文字能力需升级，不静默丢弃文字。新增 Rust 兼容 2 项与图片/混合输入浏览器模拟通过；改动包含 Rust 后端，需重新启动更新后的桌面程序。（2026-09-22 已部署云端：VPS Worker 覆盖层 + Edge v15 capabilities，见 ARCH-ADJUST-PROGRESS.md；真实付费串联与桌面发布仍未做。）

- 追加修正必要旁支：从发条覆盖的下游反向补齐缺少输出的上游依赖（例如生成卡额外连接尚未产出的视觉规范），按拓扑顺序执行；已有可用输出的旁支直接复用，不运行旁支的其他消费者。视觉规范首次提炼仍暂停等待用户确认，确认后继续原流程，不重提拆分/提炼。只读核对用户实际连线后复现并覆盖「拆分→反推→文本→生成 + 未产出的视觉规范旁支」；逻辑 10 项与模拟暂停/确认/继续验证通过。

- 分层步骤先读取原图本地工程；已有完整工程且没有待处理任务时直接复用，不报价、不重新提交拆分，离线亦可复用。没有工程才创建拆分；未完成拆分/文字任务保持原恢复约束，打开的编辑面板须先保存退出。
- 反推结果文本卡纳入工作流依赖图，单元格连线可以把后续生成纳入同一次触发，循环检测、失效传播和运行锁定同时识别此关系。重跑更新已有结果文本卡并保留单元格 ID；本次上游产生的文本在上游完成后读取，普通外部文本仍按启动时内容冻结。删除的单元格不静默改绑。
- 模拟执行覆盖已有分层不请求云端、离线复用、拆分→反推→文本单元格→生成读取本次新内容、原卡片/连接复用；工作流逻辑 9 项、Rust 工作流 5 项及类型检查/构建通过。未调用真实付费模型或发布安装包。

### 多图反推与运行进度（2026-09-21，源码未发布）

- 反推输入允许多张图片，同时提交独立反推请求；结果按输入顺序汇总，不按完成顺序排列。提交前持久化每张图的任务 ID，本机与 Cloud 均使用独立取消句柄；普通反推入口保留原队列及独立 legacy 句柄。任一失败取消本批剩余任务、等待请求结束并停止下游，手动停止仅影响对应流程。多图成功后创建原生文本卡，固定「素材 / 提示词」两列，表头之外每个素材占一行，素材列为名称，提示词列为该图自己的完整反推结果。单元格沿用文本端口；结果卡与反推卡连线、持久化并即时刷新到画板。聚合提示词与维度输出继续可用。
- 发条围绕钥匙杆轴旋转，流程执行到下游时继续显示运行状态；悬浮或键盘聚焦显示本次完成步数、当前步骤、各步骤状态及错误。拆分展示提交/排队/处理/导出阶段，反推展示并行总数与已完成数量；没有真实百分比时不伪造百分比。
- 单层导出保留完整且底图在首位的工程结构，只将目标层设为可见，避免前景层孤立成为第零层后触发「分层工程数据无效或超出大小限制」。原生校验及大小限制不变。
- 工作流图片预览复用 `canvasAssetMediaPath`，PNG/WebP 等优先读取原图，避免旧 JPEG 缩略图丢失 alpha 后露出黑底。浏览器像素回归覆盖全透明、半透明及不透明彩色前景；不修改分层原始像素或既有缩略图文件。
- 验证：工作流逻辑 8 项、模拟拆分两层→逐图反推→结果表、Chromium 实际文本卡渲染/即时刷新/连线/发条提示、Rust 分层 3 项、TypeScript 与生产构建通过。未调用真实付费模型，未打包或发布。

- SQLite `0031_canvas_workflows.sql`：每项目一份有版本号的 JSON，含可编辑卡片、端口连线、缓存结果及执行记录。`runs` 保存多次独立执行，旧 `run` 兼容读取并保留最近一次镜像；`0032` 将项目删除保护扩展到所有活跃运行。与历史 `canvas_nodes/edges` 分开，避免可编辑连线改写生成溯源。
- Tauri `canvas_workflow_get/save` 使用 revision 比较更新；失败显示重试入口并阻断新提交。配置变化清空本节点及下游结果，布局变化不清结果。
- 定义先保存再执行；每次运行建立独立创作线程，项目与账号身份固定。控制器独立于 React，切换画板不重发任务。
- 普通生成复用 store 的 provider 门控与任务入库，预写 job ID，恢复时只查既有任务；未知提交状态须人工检查后停止，重新运行才会重新提交。工作流反推并行调用既有理解接口，后端 provider 权益与服务限制继续生效，取消按任务 ID 隔离；未知反推不自动重提。
- 技能与视觉规范在人工环节暂停；分层直接提交、轮询并保存。拆分复用面板的报价、PNG/尺寸校验、幂等请求、本地 pending 与历史保存契约；提交前先保存任务标识及 pending，恢复只查询原键，结果未知保留 pending 可从原图右键取回。同一图片的拆分互斥，打开的分层工程须保存退出后才可启动，避免覆盖编辑。每次运行仅锁定执行范围及其依赖的上游工作流卡片；无关卡片可编辑、运行，模型服务/账号并发限制保持原约束。
- 停止只取消对应运行的可识别任务，再释放该运行的锁。取消失败保留锁定并报错，允许重试停止；迟到结果不覆盖停止后编辑。模型服务/账号并发限制保持原约束。
- 文本卡单元格在启动时冻结当前正文，避免运行到后续步骤时读取期间修改的内容；旧记录没有快照时沿用原读取兼容。未参与执行的分支不纳入执行顺序。
- 执行抛错后流程进入失败终态，停止调度下游并解锁编辑；错误留在卡片上。人工确认或任务尚未完成仍属于正常等待。
- 生成前持久化 `sessionNodeIds`，原生创建会话时据此锚定生成卡右侧并避开卡片，跳过普通创作自动落位；输出端口持续连到对应会话，重载/恢复保留位置。
- 运行中/等待中的工作流阻止删除项目；输入与输出素材纳入项目引用，其他项目中的工作流引用参与删除保护。

## 首版边界

### 视觉规范卡片增量（2026-09-21，源码，未发布）

- 左侧调色板按钮新增视觉规范卡；文本和图片输入，金色菱形「视觉规范」输出；生成/技能卡新增同类型单份输入，不能接到文本/图片端口。
- 「从图片 / 文字提炼」接受任选图片、任选文字或组合输入；图片复用 v2 品牌观察，缺失时沿用串行队列补齐。名称最多 80 字，合并文字最多 4000 字，图片最多 500 张。
- 提炼后生成独立 draft，打开原规范详情，沿用微调、核对、试画和保存。工作流暂停，保存后点击继续，输出 confirmed ID/version/summary；下游通过既有 visualProfileId 编译冻结 capsule，不改全局选择。
- 「选用已有规范」直接复用已确认版本，不再分析/提炼。新提炼缓存按图片 ID 集合及合并文字匹配；输入不变时重跑复用，输入变化后新建版本。「重新提炼」显式清缓存；改名只用于下一次新提炼，不改写已保存版本。
- 使用 `workflow:<projectId>:<nodeId>` 作为版本来源键，不创建集合、不移动素材、不把规范生命周期绑定到项目。source_payload v2 envelope 保存 cards 和 requirements；来源读取兼容旧数组，删除保护仍扫描全部规范来源。
- 卡片生成的已确认规范同样进入全局可选列表。已归档版本禁止作为新输出；运行/重启中断不会自动重提未知提炼任务。

云协议与发布顺序：

1. 更新 visual-profile Worker 及 `brand-visual/workflow.md`。Worker 支持输入 schema 1/2；图片观察和旧集合提炼保持原路。文字阶段使用同一服务内的新归纳提示词，不增加 Agent/Harness；纯文字只执行文字归纳。明确品牌标注程序保留，模型结果校验类别、极性、长度和真实来源 ID。
2. 更新 Edge `visual-profile`：schema 2 增加 requirements，允许非空文字配零图片；沿用原账本、幂等、队列和 TTL，无新增云数据库迁移。`capabilities` 返回 input_schema_version=2；必须先更新 Worker/提示词再开放 Edge 能力声明。
3. 更新桌面构建。图片分析前检查云端能力，旧服务缺少能力时阻止调用；取回规范后仍须用户确认。现有规范选用不依赖新提炼接口。

本轮验收：Rust 视觉规范相关 30 项通过；新增 Chromium 组件/模拟执行覆盖纯文字草稿、真实保存面板、下游生成、缓存重跑、修改输入、新旧版本选择、图片观察、技能参数、已归档版本及旧云阻断；原工作流运行回归通过。Worker 新增纯文字/混合规则与 v2 消费测试；桌面/Worker 类型检查和 Edge Deno 检查通过。未调用真实付费模型，未发布安装包。（2026-09-22：第 1/2 步已部署——VPS Worker 覆盖层镜像与 Edge `visual-profile` v15，同时上线 `generate-proxy` v37 的 transparent 透传；第 3 步桌面发布与真实付费串联待做。部署与回滚证据见 ARCH-ADJUST-PROGRESS.md。）

### 其他首版边界

- 支持保存后重跑、卡片复制、替换素材/参数；尚无跨项目模板库、条件分支、循环、定时或批量触发。
- 工作流卡片接入画板统一选区：可与图片、文本卡混合框选，Ctrl/Cmd 点选增减，拖动标题或选区内原生卡片整体移动；参与吸附辅助线和右键「整理」，移动/整理可 Ctrl/Cmd+Z 撤销，Esc/指针取消恢复原位置。按卡片实际显示尺寸取边界，适应内容额外保留发条/参数栏空间。坐标沿用工作流保存队列，不改参数、连线、产物或运行记录；正在运行的卡片保持锁定。尚无工作流卡片分组或批量删除，删除仍使用卡片自身按钮；混合选区不显示原生层级/移出菜单，也不执行部分删除。
- 生成卡复用图片生成链路，采用普通文本编辑；尚未接入底部对话框的富文本维度 chip、多轮会话与视频参数。
- 反推与分层的聚合端口可在执行前连接；细分维度/图层端口在结果出现后展开。技能目前是两个固定描述项，不是任意用户 Skill 的自动 schema 解析。
- 关掉应用后不会后台继续调度下游；重新打开后显式继续。分层与 Agent 不自动越过人工确认。
