# 文本编辑器 Markdown 写作交互 — 2026-11-05

## 目标与复用

按用户要求以 Notion 的常见写作交互为基准，补齐行首 Markdown 快捷转换与选区浮动工具栏。沿用已接入的 Plate 文档组件，不引入另一套编辑器。

- 开工读取 PROJECT、文本专项、UI 规范、开发计划与复用地图，核对 `TextPlateEditor`、`TextBlockActions`、文档编解码和 `usePortalTarget` 的生产调用。
- 参照 [Notion 官方快捷键](https://www.notion.com/help/keyboard-shortcuts)、[Plate 输入规则](https://platejs.org/docs/autoformat) 与本机锁定版本源码：基础／列表插件已经存在，但没有注册 Markdown 输入规则，现有格式栏只固定显示。
- 复用 Plate core 的 `rule.blockStart`／`rule.mark`、公开列表变换和历史记录；固定／浮动栏共用一组格式按钮。新建的两个组件文件只承担输入配置及选区 UI，不扩展到 ProseMirror 创作框。

## 行动记录

1. 先给正式工作区 fixture 增加空白文档模式，编写真实键盘测试。基线在标题、列表、引用转换和选区浮层处按预期失败；首次沙箱运行不能连接 localhost，放行本机隔离浏览器后完成行为基线。
2. 注册标题、无序／有序列表、引用、粗体／斜体／行内代码规则。块转换单独进入撤销批次，原始源码块保持字面内容，中文组合输入期间不触发快捷转换。
3. 共用固定／浮动格式操作，列表按钮改用真正的开关。浮层跟随正文内选区，保留焦点和选区，提供当前格式状态、Esc 收起与 Alt+F10 键盘入口。
4. 验证发现 Portal 从 body 迁移到工作区后仍观察旧节点，导致窄屏定位不准；让目标变化重新绑定观察。DOM 选区先于 Plate 选区更新时不提前展示可操作浮层。
5. 扩展连续格式操作测试，发现直接将段落改为引用类型会触发 Plate 容器规范化并丢失选区；按插件契约改用包装／解除包装，快捷输入和按钮一致，不用强行重设焦点掩盖问题。
6. 验证选区跨段、中文组合输入、滚动后隐藏、原素材详情共用编辑器、深浅主题及 900px 窄屏。回归已有段落、素材和 Agent 操作；同步 PROJECT、文本专项及本地复用地图。
7. 使用隔离源码副本执行质量工具，避免变异测试修改工作区。仅提交本轮文件及 PROJECT 的相应句子，其余并行改动保留。复用地图原文件受 Git 忽略，保持本地更新，未强行纳入整份无关历史。
