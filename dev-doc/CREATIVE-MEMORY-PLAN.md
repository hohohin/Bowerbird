## 0. 目标与首版范围

让用户主动复用的提示词成为可检索的工作资产，再从真实复用行为提炼有来源、有范围、可修改的创作偏好。用户确认偏好并打开应用开关后，系统用少量相关规则辅助下一次生成。

产品链路：

```text
点击复用 → 本地记录 → 成功载入 → 实际提交生成
               ↓           ↓          ↓
          常用提示词库 ← 聚合统计与来源关联
               ↓
       定期增量分析 → 偏好候选 → 用户确认
                                      ↓
当前任务 + 已选视觉设定 + 相关已确认偏好 → 冻结输入 → 生成
```

### 0.1 首版包含

- 记录用户主动复用生成提示词的行为，覆盖素材右键、普通生成详情、画板结果和 Agent 结果等对应入口。
- 图片、视频及 Agent 原始意图均可进入记录与常用库；通过媒体类型、来源类型区分。
- 原文、参考关联、维度文字快照、来源与目标项目，以及后续提交关系可追溯。
- 常用库支持搜索、按项目/媒体筛选、按次数/最近时间排序、收藏、再次复用、删除和排除学习。
- 本地维护项目偏好与全局偏好；自动分析只产生候选，逐条或批量确认后生效。
- 普通图片生成与当前统一 Agent 接入只读偏好；Agent 的图片/HTML 输出共享同一冻结上下文。
- 学习与应用分开控制，生成前查看本次偏好并可临时排除，历史记录可解释。
- 云端固定文本提炼任务，复用已有身份、权益、计量、Worker 与临时数据治理。

### 0.2 后续范围

- 视频记录和常用库首版支持；视频生成自动注入放在后续专项，首版明确显示“视频暂不应用创作记忆”，不把图片偏好无条件拼入视频提示词。
- 高置信度偏好未经确认自动生效、基于结果图自动判断满意度、全库扫描、聊天记忆、跨设备同步、团队共享均不进入首版。
- 不新增 Agent Harness、通用模型循环、向量数据库或本地模型；不把历史生成次数追认为复用次数。
- 偏好不决定工具权限、预算、provider、生成数量、视频参数或是否新增动作。
- 不改造视觉规范的主动提炼与确认流程，不把自动学习写入视觉设定。

## 2. 用户体验与开关契约

### 2.1 常用提示词库

创作器提供“常用提示词”入口，管理界面复用现有 ModalShell。设置的“创作记忆”可以进入同一管理界面，不再造一个侧栏项目/会话对象。

列表展示原文摘要、媒体类型、成功载入次数、实际提交次数、最近复用时间、项目和收藏标记。点击展开原文、参考缩略图（仅仍存在时）、维度快照和事件记录。原始点击总数在详情中展示，不用于默认频繁排序。

- 排序默认按成功载入次数，同次数按最近载入时间；提供最近使用排序。
- 搜索采用现有 SQLite 文本检索方式，首版不做语义搜索；分页读取，不能把全库快照一次载入前端。
- 收藏代表固定到常用库，不自动等同于确认其中每项偏好。
- “再次复用”走既有项目路由和参考校验，不修改源条目。编辑后提交保存为新的输入快照，并关联原条目。
- 原参考文件丢失时保留文字，明确提示缺失；不能悄悄换成同名素材。
- 快照用于学习与追溯；再次复用仍遵守现有维度按身份读取当下值的产品契约，并在发生变化时提示。不得借本专项把普通复用静默改成冻结旧维度。
- 删除条目清除其复用事件/快照与学习证据，不删除原生成任务、中央素材或账单。删除前说明影响已确认偏好的哪些来源。

### 2.2 创作记忆设置

| 控制 | 关闭后的行为 | 保留内容 |
|---|---|---|
| 保存复用历史 | 停止新增复用事件及其后续行为记录 | 已有常用库、已确认偏好；仍可手动管理 |
| 从复用记录学习偏好 | 不创建新的云端提炼任务，取消本地待发任务 | 复用库与已确认偏好；不自动重新开启 |
| 生成时使用偏好 | 新任务不编译或发送偏好 | 学习可独立继续，候选等待确认 |
| 本次不使用记忆 | 当前草稿新提交不带偏好；不改变全局开关 | 后续新草稿恢复全局默认 |
| 项目“允许从这里学习” | 当前项目的输入不得进入新的分析批次 | 普通复用历史及手动偏好管理 |

“学习关闭”不等于“删除记忆”，“应用关闭”不等于“停止记录”。界面分别说明；用户可一键关闭学习和应用。

云任务已发出后关闭学习：尽力取消尚未调用模型的任务；已经发生的调用不能当作未发生。其结果不得自动进入候选，标记为停用期间结果，由用户重新开启后主动决定是否导入。不得因此自动退款、重复请求或恢复开关。

### 2.3 偏好管理

两组视图：待确认 / 已记住。每条包含规则、适用任务类型、项目或全局范围、来源数量、最近证据时间。

- 候选可编辑、确认、忽略、排除该类建议；新证据不能静默改写已确认规则。
- 用户确认时看到范围与适用类型；全局候选不能默认混入项目批量确认。
- 已确认规则可停用、编辑成新版本、缩小范围、删除。手动写入和显式确认支持避免项；自动提炼首版只产生正向视觉倾向。
- 同范围、同适用类型的冲突候选并列展示，用户选定后替代旧版本；禁止把“低饱和/高饱和”平均成一条规则。
- 手动“记住这条偏好”可以没有行为证据，以本次用户确认作为显式依据。

### 2.4 生成前与生成后

创作器显示“本次带入 N 条偏好”，展开可看正文、来源范围、排除某条或本次全部关闭。该文案表示已加入上下文，不宣称模型一定采用。

最终发送前用草稿 revision、设置 revision、偏好版本和视觉设定 hash 校验预览；不在用户看过之后静默加入新分析出的偏好。发生变化时刷新预览，再使用同一冻结快照提交。

生成历史分别保留用户原文、展开输入、视觉规范和偏好附加块。复用操作取用户原文和显式引用，不将已注入块作为用户文字再次载入。界面支持查看本次实际发送的偏好，不显示模型未提供的“真实采用原因”。

## 3. 记录与证据规则

### 3.1 三个时间点

1. `clicked`：用户主动发起复用时产生稳定 `reuse_event_id`，先记录可知的来源身份；原始输入已在内存时一起冻结，需异步读取时在读到后补齐快照。读取失败也保留失败点击，但不能作为学习证据。后台重新载入、恢复草稿、重试 IPC 不创建新事件。
2. `loaded`：正确目标项目的编辑器完成该请求的消费确认。失败/路由过期只留失败结果，不计成功复用。
3. `submitted`：用户以关联草稿提交，普通任务已经本地入队，或 Agent 创建请求已在本地持久登记。不是 provider 返回成功；远端响应未知也不重复记。

连续主动点击可有多条 clicked 事件；每个请求只能成功 loaded 一次。同一点击加载到错误项目绝不能计入目标项目。每次明确发送有独立 submission ID，自动重试沿用该 ID。

重复载入覆盖草稿时，只有当前有效的复用来源关联下一次提交；首版不支持把任意粘贴文本自动认作多个复用来源。草稿被清空或替换后解除来源关联。不同结果产生相同原文时仍保留各自来源。

### 3.2 原文、展开与来源

一个快照区分：

- `editor_raw`：用户可见文本/chip 表达，用于显示和复用。
- `user_expanded`：用户文字与显式选中参考维度展开后的文本，系统偏好注入前冻结。
- `segments`：text / reference / dimension / preset 等片段的来源、引用 ID、文字快照、来源 hash；系统附加块独立保存，不混进可学习输入。
- `reference_manifest`：资产 ID、必要的媒体角色与稳定身份，不复制原图；不把绝对路径、账号、签名 URL 发给分析模型。
- `provenance_quality`：`structured` / `legacy_raw` / `legacy_unknown`。

新记录必须有 structured 来源。旧记录有可靠 prompt_raw 时可进入常用库和低权重候选证据；只有完整展开 prompt、无法区分系统附加内容的旧数据仅供复用，不参加自动学习。不得用正则盲删一段看起来像“偏好”的用户文字来伪造可靠原文。

### 3.3 聚合身份

快照 hash 基于带版本的规范 JSON：原文（仅统一换行）+ 显式引用身份/角色 + 维度内容 hash + 媒体类型。不得删除标点、数字、否定词或把主体词抹掉来做精确去重。

默认列表按该身份聚合，来源项目仍单独计数。相同文字但不同参考或维度快照不是同一精确条目。首版不做语义合并；后续相似归组也不能覆盖原文。

### 3.4 独立证据与防回流

- 点击是弱信号；分析候选至少需要成功载入，实际提交为更强信号。提交后生成成功不是满意评价。
- 候选累计按独立复用链计数：同一来源快照的重复点击、重试、由该快照直接衍生且相关片段未改的后代，按项目和自然日最多贡献一次。
- 原文被完整换掉时，仍可统计“曾复用”，但不为原文规则增加提交证据；仅保留片段支持相应候选，不能把机械 diff 的删除直接推导为厌恶。
- 系统注入、视觉规范、Agent 自己生成的执行 prompt 不成为独立用户证据。用户若明确把建议编辑为自己的规则，记录显式确认，不伪造行为频次。
- 拷贝来的同一条常用模板即使跨项目使用，也要保留共同来源；全局偏好门槛同时检查独立来源，避免一条模板的后代循环自证。
- 不跨用户汇总，不建立人群画像；“用户偏好”首版指当前本地资料库的创作倾向。

## 4. 本地数据模型与生命周期

使用 library.db，采用追加迁移，不复用遗留 `asset_prompts`。具体迁移号在 CM0 按当时最新源码分配，本计划不预占当前 0025 后的编号。

### 4.1 最小表集合

| 表（拟定名） | 关键字段与职责 |
|---|---|
| `prompt_reuse_snapshots` | id、schema_version、content_hash UNIQUE、editor_raw、user_expanded、segments_json、reference_manifest_json、media、provenance_quality、favorite、learnable、created_at |
| `prompt_reuse_events` | id/request_id UNIQUE、snapshot_id（异步读取前可空）、source_kind/source_id/source_turn_id、source_project_id、target_project_id、thread_id、parent_reuse_id/root_lineage_id、clicked_at、loaded_at、load_status、submissions_json；submissions 保存唯一 submission ID、执行 kind/id、提交快照 ID、时间 |
| `preference_analysis_batches` | id、scope_key、evidence_manifest_json、input_hash、extractor_version、idempotency_key UNIQUE、remote_job_id、status、policy_revision/memory_epoch、watermark、candidate_result_json、usage_summary、error_code、created_at |
| `creative_preferences` | id、version、scope_key、applicability_json、category、value、status、origin、confirmed_at、last_evidence_at、confidence_label、rule_key、supersedes_version、created_at；版本唯一 (id,version) |
| `creative_preference_evidence` | preference_id/version、event_id、snapshot_id、segment_ids_json、evidence_kind、evidence_hash；复合唯一约束防重复计数 |
| `creative_preference_suppressions` | scope_key、rule_key、applicability_json、evidence_fingerprints_json、suppressed_before_watermark、reason、created_at；保留最小防复活信息，不保存被删全文 |

设置沿用本地设置持久层，包含 record/learn/apply、项目排除、分析费用授权上限、policy revision、memory epoch 和分析水位；不另建账户系统。CM0 核对现有设置存放方式后采用同一权威写入口。

聚合次数查询事件表计算，先不维护容易漂移的第二份计数表。提交关系首版是单事件下的小数组；若既有任务关联表能无损承载，CM0 可采用关联表，但不得同时维护两套权威。

### 4.2 写入与并发

- 原始输入已知时，snapshot upsert + clicked event 在同一事务；异步读取时先写 clicked，再用同一 request ID 事务补齐快照。只有快照完整且目标编辑器确认后才能进入 loaded；loaded/submitted 按稳定 ID 幂等更新。
- 复用日志写入失败不得阻止原有复用动作；明确提示“提示词已载入，复用记录保存失败”，不显示虚假的统计成功。
- 偏好存储不可用时普通创作仍可继续，明确提示本次未带入记忆；已经创建的任务不能改变冻结输入。
- 分析批次提交前先本地持久化 idempotency key 与证据 manifest，再请求云端；崩溃恢复只查询/接续原任务。
- 候选导入、用户编辑/删除、项目删除和清空操作带 revision/epoch 校验；迟到响应不得覆盖用户新操作。
- 删除事件后，孤立快照垃圾回收；仍被常用收藏或历史执行引用的必要快照按对应生命周期保留。

### 4.3 范围与删除

- 项目范围取实际成功载入/提交的目标项目，来源项目只用于追溯。provisional 项目未落实时不生成项目偏好，不擅自转为全局证据。
- 项目删除：删除其项目偏好及候选、停止相关分析，移除该目标项目行为的学习资格；中央常用文字条目可保留并标记“原项目已删除”。这些证据不能因 project_id 置空而晋升全局。
- 删除参考素材：不增加素材物理保留引用，不阻止现有清理；库中缩略图和再次复用引用降级为缺失，已有文字快照可用。
- 删除学习证据：候选重新核验/失效；已确认偏好保留为用户确认规则并标“来源已删除”，不偷偷改规则。用户另行删除该规则时建立 suppression。
- 删除偏好：未来不再注入；同规则同范围和同一批旧证据不得再次建议。对模型换措辞，用规范分类/适用范围及证据集合校验，不能只比较展示句子的 hash。仅有新增独立证据时，仍需重新确认才可恢复。
- “清空创作记忆”：删候选/偏好/学习快照与分析状态，递增 epoch，并把保留复用记录截至清空时的水位标为不学习；继续记录未来复用。默认同时关闭学习和应用；以后重新开启也不自动重扫旧证据。可单独选择一并清空复用库。
- 执行历史中的实际发送快照不因清空记忆而改写；界面说明“历史任务仍保留当时输入”，历史删除遵守现有契约。不能宣称清空记忆等于全库抹除文本。

### 4.4 本地资料库与账号

首版偏好归本地资料库，不随 Cloud 登录自动同步。分析授权记录本地资料库身份与 Cloud 账号；退出/切换账号撤销待发云分析授权，不能用新账号继续旧队列。重新开启时显示数据范围和扣费账号。发送前和接收后检查资料库、账号与 epoch，切库/切账号后丢弃对当前上下文不再有效的响应。

## 5. 偏好提炼

### 5.1 可学习内容

首版自动学习白名单：风格、配色、构图、光影、材质/笔触、文字与版式倾向。规则必须携带适用任务类型，例如 product_poster / portrait_illustration / document_layout，不能只写“用户喜欢蓝色”。

不自动抽取主体身份、品牌、客户信息、精确文案、联系方式、敏感属性、账号行为或技术预算。现有 v1 包含 subject/workflow 分类不表示本专项允许自动推断它们。手动明确规则可兼容已有分类，但仍受应用范围与权限边界限制。

仅从用户主动使用过的文字提炼，不上传图片、不触发反推/Vision，不把所有素材 caption 自动纳入。参考维度属于“用户选择了这段信息”的证据，不等于用户确认其中所有描述。

### 5.2 候选门槛（首版可调配置）

| 候选范围 | 最低独立依据建议 |
|---|---|
| 项目 | 同一适用类型下至少 3 个独立证据单位，覆盖至少 2 个自然日，其中至少 2 个发生实际提交 |
| 全局 | 至少 3 个非排除项目、3 个自然日、6 个独立证据单位和 2 个独立来源；不能只由同一模板后代构成 |
| 手动记住 | 不要求频次；用户明确提供/确认规则、范围和适用类型 |

频次、时间、来源及否定/冲突由本地确定性规则计算。模型提供候选和证据定位，不能自报一个 confidence 就绕过门槛。置信度显示“证据较少/重复出现”等可解释标签，不展示伪精确百分比。

默认分析最近 90 天的合格证据。年龄仅影响候选排序，不能自动把用户已确认的偏好作废；已确认偏好直到用户停用/修改。若旧证据逐渐不足，待确认候选不继续强化。

### 5.3 调度与批次预算

初始建议：距离上次该范围成功分析至少 7 天，且有至少 10 个新的合格独立证据单位时触发。用户可点“现在分析”跳过时间/数量触发门槛，但仍受候选最低证据和费用上限约束；不足时本地说明原因，零模型请求。

- 启动、恢复联网及成功提交后检查到期状态；仅应用运行时调度，不创建操作系统定时任务。
- 每个资料库最多一个在途分析；每 24 小时自动启动至多一批。长时间关闭应用后只处理一批，不按漏掉的周数补跑。
- 每批最多 50 张证据卡、输入 UTF-8 48 KiB、最多 12 条候选、每条规则最多 120 字符；输出 schema 有限，模型无业务工具。
- 同一范围选取新证据与必要历史佐证，至少给新证据留半数名额；未选中的数据保留待处理，水位不能越过未分析证据导致永久漏记。
- 超长单卡只取带位置/来源的完整可学习片段，记录省略范围；无法安全拆分的卡跳过并报告，不静默截掉否定句后继续学习。
- 每批至多一次提炼模型调用；JSON 无效时本地校验拒绝，不自动开启修复循环。允许用户以后重新分析，需使用新批次并显示费用。
- 普通网络读取可退避重试；模型提交结果未知只恢复原任务，不换 key 重发。达到预算/额度时停止自动分析，记录原因。
- 完成后无合格候选也推进已处理集合，避免反复花钱分析同一批。

阈值是候选生成条件，不是自动确认条件。CM7 根据实测修改配置时必须记录版本和依据。

### 5.4 云端固定任务

建议新增 `preference-extract` 用户侧入口和 `preference_extract_jobs` 短期任务表，在现有 Worker 进程内增加固定文本任务消费处理；不新增 Agent 会话、Runner 或工具 loop，也不占用用户创作线程。

- 复用现有鉴权、RLS、FeaturePolicy、幂等、hold/usage/settlement、租约/恢复、私有 artifact 与 TTL 基础设施。新增 service 与权限项由 CM0 明确，不能冒充 caption 或 visual_profile 服务扣费。
- create/get/cancel 均验证账号所有权；相同 key 不同 input hash 返回冲突。任务响应保留 job ID、状态和 usage，不返回其他账号内容。
- 输入是匿名证据卡编号、白名单文字片段、适用类型、必要的聚合支持统计；跨项目只发送临时代号。不发送完整行为日志、真实项目名、路径、URL、图片和其他项目原文。
- 跨项目全局候选优先使用各项目已有候选规则摘要与本地验证后的支持统计；只发送用户允许学习的范围。模型返回的卡 ID 必须属于冻结 manifest，伪造证据整条拒绝。
- 本地仍保存“模型卡 ID → 真实事件/片段”的映射。云端候选是低信任数据，桌面再次校验才能落为 pending，永远不能直接写 confirmed。
- 输入中的指令、引用文本与偏好均不改变提炼器系统规则；输出不得带工具请求、授权或执行计划。
- 建议内容 TTL 24 小时并提供主动删除入口；最终数值按现有私有存储机制落地。账单仅保留必要计量/状态/hash，不留提示词正文。
- 桌面离线超过内容 TTL 后标记结果过期，不自动再次扣费生成候选。重启查询同 job；未知结果不因本地清空而创建第二次调用。

### 5.5 费用与失败体验

本地记录、聚合、管理及偏好选择不调用模型。云提炼显示单次最高费用与月度自动分析上限，由用户开启时授权；默认没有该授权则不自动外发。价格配置缺失时隐藏启用付费分析动作，常用库及手动偏好正常可用。

提炼失败不能阻止生成。后台无候选、无新证据或未到期不弹打扰；有新候选显示轻量数量，有失败/费用上限显示设置状态。日志仅记批次 ID、数量、hash 和安全错误码。

## 6. 偏好选择与生成注入

### 6.1 输入优先级

系统策略/权限边界独立且不可被任何偏好覆盖。创作内容的优先级：

```text
本次明确要求 > 已选视觉规范 > 项目已确认偏好 > 全局已确认偏好
```

偏好仅补未指定的选择。选择器不能改变尺寸、张数、参考角色、主产品、精确文案、工具路线和保持项；局部修改任务默认不自动带入整体风格偏好，用户仍可在预览中主动选中适用项。

### 6.2 首版相关性选择

- 先过滤开关、项目/资料库范围、confirmed+enabled、媒体和适用任务类型。
- 本地规则使用编辑器已知媒体、结构化任务模式及少量显式类型关键词匹配；不为每次生成增加一个分类模型。无可靠类型时不自动选中专用偏好，允许用户从管理器手动选。
- 项目规则优先；同分类冲突时全局项退出。同范围互相冲突的确认规则通过管理界面处理；未解决时该冲突组不自动带入。
- 可确定的显式冲突（已指定色彩/构图等）在本地排除；开放自然语言冲突无法完全用规则检测，注入说明再次要求明确任务优先，CM7 用真实模型案例验证。不能声称字符串匹配保证语义不冲突。
- 最多带入 5 条，每条最多 120 字符，总正文最多 600 字符；记录 selector version 与排除原因。不为凑满条数补不相关规则。

### 6.3 冻结格式

本地新增 `GenerationPreferenceSnapshot v1`，至少包含：

```ts
type GenerationPreferenceSnapshot = {
  schemaVersion: 1;
  projectId: string;
  selectorVersion: string;
  policyRevision: number;
  memoryEpoch: number;
  userInputHash: string;
  visualProfileHash?: string;
  facts: Array<{
    preferenceId: string;
    version: number;
    sourceScope: "project" | "global";
    category: string;
    value: string;
    applicability: string[];
  }>;
  compiledText: string;
  hash: string;
  frozenAt: string;
};
```

snapshot hash 使用固定规范 JSON，校验对象中不包含自身 hash 字段。事实内容和来源版本都参与 hash。空选择不产生偏好附加块。

首版传输复用 PreferenceCapsule v1 的已确认事实语义；sourceScope/规则 ID 等审计元信息保存在新快照，不硬塞进旧 v1。面向当前项目编译合并后的胶囊，任何项目偏好必须属于当前项目；全局事实只是在本地选择后进入本次输入，不外发别的项目证据。

传输分类沿用现有白名单：配色映射 palette，构图/版式映射 composition，材质/笔触映射 medium，风格/光影映射 style；更细的学习分类保存在本地，不向 v1 新塞 lighting 等枚举。手动避免项进入 avoid。用户确认的手动规则以确认记录作为一条显式依据，不能因没有行为频次而伪造多次复用。已有 confidence 数值只作兼容字段，不用于越过本地门槛或宣称概率已校准。

若 CM0 证明 unified 需要额外传输字段，新增明确版本并保持旧请求可解析，禁止以同版本悄悄改变 schema。Rust/Edge/Worker 的字符长度定义与 hash 规范一致，包含中文和 emoji 契约测试。

### 6.4 普通图片生成

在后端已有视觉设定组装附近加入单一偏好编译接缝，用户输入/维度展开、视觉设定、偏好块各自保留。UI 传已选规则身份与预览 revision，Rust 从当前本地权威核验并冻结；不能只信前端任意拼出的“系统偏好”。

参考附加块：

```text
以下为用户已确认、仅适用于当前任务的创作倾向，只用于未指定的视觉选择。
本次明确要求和已选视觉规范优先；不要改变主体、文案、数量或局部修改的保持范围。
适用：产品海报。倾向：低饱和配色、清楚的文字层级。
```

同一 job 快照只注入一次，provider adapter 不再次拼接。Cloud、即梦图片和本机 Codex 图片分别检查最终实际请求；未支持的能力明确提示，不静默改变引擎。

复用后新建任务按当前开关选择当前偏好。技术重试、恢复轮询沿原快照；用户主动重新编辑创建新任务则重新预览。不得把二者都叫“重试”而混用新偏好。

本机续轮若沿用 provider session，旧偏好可能已在上游历史中，关闭应用不能抹去已发送历史。首版在用户要求“不使用记忆”的新提交中，若旧 session 带过偏好，创建新的 provider session 并沿用本地线程关系；不得显示未使用却继续复用含偏好的旧 session。

### 6.5 统一 Agent

Rust unified manifest → agent-run Edge 校验 → unified schema → 初始 checkpoint → DSH 规划/执行上下文全部纳入同一个冻结快照。

- 首次规划提供少量只读偏好，后续通过现有 `read_context` 获取；压缩和消息历史由 DSH 管理。
- 执行阶段使用同一个 snapshot；偏好只能落实为已授权计划范围内的视觉选项，不能增加工具步骤/预算。
- 计划和展示保留偏好 hash；重启、提问、审批和结果修订沿原 Run 输入，不读取桌面最新长期记忆替换已批准计划。
- 正在运行时关闭应用只影响新任务；现有任务提示“此任务已使用此前偏好快照”。若用户要改当前 Run 的偏好，应取消后重新创建，不改后台既有审批。
- 校验胶囊有效期发生在新任务接收时；任务恢复不以当前时间把当时有效的冻结上下文改写或升级。沿既有 Run 生命周期限制处理过期任务。
- HTML 生成仍遵守精确原文、视觉规范和工具权限；无独立 HTML 记忆库/学习器。

## 8. 验收矩阵与质量门槛

### 8.1 必须通过的确定性场景

| 编号 | 场景 | 预期 |
|---|---|---|
| E01 | 一次点击被重复消费/IPC 重发 | clicked/loaded 各最多一次 |
| E02 | 主动连点十次，同项目同日同来源 | 原始点击保留，独立证据最多一个 |
| E03 | A 项目复用请求未完成即切到 B | 不在 B 记成功/注入 A 偏好 |
| E04 | 同原文，不同参考/维度内容 | 不误合并；快照仍解释当时内容 |
| E05 | 复用后未发送、发送失败或 provider 未知 | 行为状态准确，未知不当满意/不重复记 |
| E06 | 同项目连续做红色品牌包装 | 不自动产生全局“喜欢红色/该品牌” |
| E07 | 不同项目和类型分别用低饱和、高饱和 | 各范围并存，无平均偏好 |
| E08 | 模型把商品名、客户文案写成偏好 | 候选拒绝且无长期写入 |
| E09 | 图片提示词经十代复用，系统持续注入同一偏好 | 系统文字和同源后代不构成独立强化证据 |
| E10 | 用户删除候选/偏好，旧批次迟到或换措辞 | suppression/epoch 生效，不重新出现/生效 |
| E11 | 关学习开应用；开学习关应用 | 前者无新分析但可使用已确认项；后者只产候选，不影响生成 |
| E12 | 本次明确要求与偏好冲突/局部改图 | 可确定冲突被过滤，局部编辑默认不带全局风格 |
| E13 | 已选视觉设定与个人偏好冲突 | 视觉设定优先，个人项不能改 must/avoid |
| E14 | 超长、未知分类、错误证据 ID、指令注入 | 本地/服务端拒绝，不截坏原文后继续学习 |
| E15 | 偏好确认与发送同时发生 | 预览与发送同一 revision/hash，无静默增加 |
| E16 | Agent 审批前后修改偏好、执行中重启 | Run 原快照不变，不重复工具/计费 |
| E17 | 应用关闭、跨越分析周期再启动 | 至多创建一批，不逐周补跑 |
| E18 | 云端成功但本地响应丢失/过 TTL | 查询原 job；过期显示说明，不自动重发扣费 |
| E19 | 切账号/切库/删项目期间分析返回 | 不串写，不把删除项目证据转全局 |
| E20 | 旧数据只有展开 prompt | 可复用；无可靠来源时不可自动学习 |
| E21 | 清空记忆但保留历史任务 | 新任务无偏好；历史仍准确显示原输入，不宣传全量擦除 |
| E22 | 用户关闭记录 | 无新复用/提交行为记录，生成历史按原职责保存 |
| E23 | 视频复用及 Agent 产出 HTML | 视频常用记录正常且不自动注入；HTML 沿统一 Agent 快照 |
| E24 | 云端提炼费用未配置/无授权/达月上限 | 不调用模型，常用库与手动记忆正常可用 |

### 8.2 真实质量验证

固定至少 20 组脱敏案例，覆盖产品海报、插画、文档排版、局部修改、探索不同风格和跨项目客户工作。每例保存输入、预期可学/不可学项及原因，不能根据实际输出事后改标准。

- 候选符合范围/证据的比例目标 ≥90%；无证据、主体/客户内容泄漏、未确认自动生效必须为 0。
- 明确任务、精确文案、视觉设定和局部保持范围被偏好破坏的案例必须逐条修复，不能以平均美观分抵消。
- 对同输入“记忆开/关”比较人工偏好贴合、任务遵循、耗时和费用；模型随机性存在，不把一次图像比较当作统计显著结论。
- 记录确认率、用户修正/删除率、单次排除率、注入命中数、每批 token/积分和时延；不把高注入率当成成功目标。
- 首版门槛是减少重复说明且可控；没有相关偏好时保持零注入也是正确结果。

### 8.3 工程检查

新增测试围绕语义不变量，使用现有 Rust/Node/Deno 框架，不写只比源码字符串的实现镜像测试。相关组件做真实 React 交互/合成 IPC，最终用 Tauri 验证 SQLite 持久化。

受影响阶段完成后运行对应 Rust tests、桌面 TypeScript/build、相关画板/生成/Agent 前端测试；修改 Cloud/Worker 时运行对应 Deno、Worker、DSH Profile 和数据库回归。最终整体验收再跑完整相关测试集，基线以 CM0 当前代码为准，不复制旧文档通过数量。

## 9. 发布、兼容与回滚

- 发布 A：CM0–CM2，本地常用库，不启用任何后台云分析。
- 发布 B：CM3–CM7，先 test-only 验证完整记忆链路；生产分析费率、授权 UI 与客户端兼容就绪后再开放。
- 新 schema 字段均有明确版本/可选缺省；老任务没有 memory metadata 时按无记忆处理，不能回填推测快照。
- 迁移先在临时库和用户库副本验证。回滚以功能关闭、兼容旧字段和保留新增表为主；不得用旧整库备份覆盖上线后的新创作数据。
- 服务端新增 capability 不自动扩大普通账号权益；entitlement、Edge、Worker、桌面真实响应共同验收，不能只测一侧类型。
- 降级/停用云提炼后已确认偏好仍可本地查看、编辑、删除；应用是否可用由独立开关和当前生成能力决定。
- 用户要求取消/清空不能造成重复 provider 请求或越权删账本。历史输入保留与内容 TTL 的差异必须在 UI 中说清楚。
- 本计划不执行部署、不发起模型调用、不改正式资料库。具体开发和发布按后续实施指令与既有授权范围推进。

## 10. 完成定义与下一步

完整首版完成需同时满足：复用链路可对账；常用库独立可用；学习输出只进候选；用户能确认/编辑/删除；按范围选择偏好并控制开关；普通图片与统一 Agent 实际接入；注入不污染学习；重试/删除/账号切换可靠；真实质量与成本有记录。

下一步从 CM0 开始，先固定入口矩阵、来源 fixture、云端商业配置和迁移基线；随后做 CM1–CM2 的本地闭环。费用配置尚未确定时可继续全部本地记录、管理和离线验收，不等待它才开始常用库开发。
