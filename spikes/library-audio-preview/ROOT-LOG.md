## 验证完成

- 第一轮基准识别到 JSON 未缓冲读写使热缓存仍需约 30–40 ms；改用缓冲读写并保留完整校验，复测为 0.325–0.402 ms，全部命中源读取为 0。原始两轮结果保留，最终数据复制到 evidence/。
- 代码审查要求补上同 revision/同 stat 的不同文件碰撞和截断 WAV；先见红再修复。CLI 原件输出覆盖也以行为测试修复。最终 Rust 11/11、Clippy、rustfmt 通过。
- 浏览器行为测试使用真实媒体；自动播放策略拒绝、延迟媒体响应、100 次跨卡片、可见范围、暂停/释放、静音波形与小时格式均通过。1200 卡片复用 6 音源，2.5 秒样本最多 21 卡片、零长任务；没有据此声称原生 FPS 或全库索引已通过。
- 亲自打开并检查深浅预览。低音量波形原先过于贴近中线，增加仅显示用的峰值归一化，播放音量不变；一小时显示改为 1:00:00。保留可操作页面与实际六文件截图。
- 删除隔离预览对 Vite 的不必要依赖，最终使用限定路径的 Node 静态服务，避免 cwd、PostCSS、HMR 端口和变换缓存干扰；正式应用构建配置未改。
- Windows 原生真实 UI 通过 asset 中点播放与移出释放，快速划过 100 次原音频请求为 0。初轮代理未转发 CSS 请求头导致布局铺满屏，修复测试代理后保留停止断言通过。
- 原生内存增长先定位到 WebView2 而非 Rust 宿主；发现 Playwright 内部也启用 Network 域。完全不连接 Playwright/Network 的裸 CDP 对照，3×100 次后的进程组私有内存为 240.33/251.18/249.05 MiB；未强制 GC。作为观测干扰证据，不宣称已证明无限时长无泄漏。
- 8 个合成源前后 SHA256 一致。普通沙箱对 realpath/canonicalize、CIM 和本机原生调试访问有限制；仅对明确的隔离验证启动使用批准执行，未放宽生产权限。Mac 原生和声卡听感未测。
- 按 PROJECT.md 的明确界面流程，向用户呈现实际预览并请求视觉/交互确认；尚未把样稿或音频类型接进正式素材库。
