Bowerbird 桌面端 UI · 面板与入口设计

依据 Bowerbird开发计划.md v1.2（六大工作流 / P0–P3 优先级 / 核心枢纽）× 当前实现现状

Bowerbird 不是"复现 Eagle"，而是「提示词 + 参考图」编排台。 因此面板设计的第一原则：让核心交互——选图选词即组装创作板（计划 §5.4）成为一等的、永远在场的入口； 其余收集 / 浏览 / 搜索 / 整理 / 分析五件套围绕它组织。

当前最大的 UI 缺口： PackPanel.tsx（创作板底层，v1.2 的"灵魂"）已写好 assemble_pack 逻辑，但 App.tsx 从未挂载它—— "选图选词 → 组装提示词 → 发 codex" 这条核心链路在前端没有任何入口。 下方设计把创作板（拟文本编辑器）作为重点新增项（标注 🔴 缺失入口）。

四、设计取舍与不做项（对齐计划 §1.4）

刻意不做的面板 / 入口（避免过度设计）：
  • 不做"生成"面板（⑥暂不做）—— 不出现文生图、垫图、ControlNet 入口。
  • 不做语义/以图搜图入口—— 无 CLIP、无 pHash 搜图（pHash 仅采集去重，不暴露为搜索）。
  • 不做内置像素编辑器—— 详情页只看，不改图。
  • 不做云同步 / 账号面板—— Local-First，仅本地库。
  • 不做 in-app API key 配置—— 看图统一走 codex CLI（ChatGPT 订阅），设置页极简（库位置 / CLI 路径 / 关于）。
建议的落地优先级（最小代价补齐核心体验）：
  • P0 新建创作板（拟文本编辑器）并挂载 + 批量模式「打开创作板」入口 —— 打通 v1.2 灵魂链路；assemble_pack 已就绪、selectedIds 即缩略图素材池，主要工作在前端编辑器控件（chips / 虚线占位 / 维度→prompt 映射表）。
  • P1 详情页 ←/→ 翻页 + "加入创作板" + 评分 —— 单文件级改动。
  • P1 底部状态条（codex 队列 / 导入进度 / 扩展连接）—— 让长任务可见，约定 5 的"不拖垮主进程"才有 UI 体现。
  • P2 标签 UI（侧栏筛选 + 详情打标）+ 搜索框升级（同步 tags/prompt_body）—— 配合 P4 的 FTS5 扩列。
  • P2 来源分组（侧栏一键切"扩展采集"）+ 视图/排序 —— 提升日常浏览效率。

本页为静态设计稿（纯 HTML/CSS，未引入 Tailwind）；视觉与 tailwind.config.js 色板一致，可直接作为 React 实现的像素参照。
