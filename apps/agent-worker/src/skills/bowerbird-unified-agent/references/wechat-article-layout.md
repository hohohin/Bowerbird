# 公众号图文排版

将用户的文字内容与配图组织为可直接粘贴进公众号编辑器的文章子树：文字保持可选中的 HTML 文本，图片保持普通 img 元素；不把整篇内容做成 SVG、canvas 或一张拼合长图。适用于公众号推文、图文排版类请求；普通网页设计或纯海报图不适用。

## 内容模型

动笔前先还原内容模型：

- 标题、导语、日期、作者或品牌行；
- 叙事段落与各自的强调方式；
- 必须逐字保留的运营事实（价格、时间、地点、步骤数字），成文后原样出现，不改写、不遗漏；
- 每张配图的编辑角色——头图、佐证、氛围、信息图、流程、行动引导或收尾——以及它所属的图注或说明。

图片按编辑含义落位而非输入顺序：头图开场，佐证图贴近它支持的论断，信息图放在它概括的事实旁边。图与图注是不可拆分的单元，排版时始终相邻成组；调整顺序时不把说明留在原图位置。

保留用户的措辞与提供的品牌素材，除非用户要求改写；参考稿中嵌入的编辑器或供应商品牌标识不搬运。

## 可移植文章子树

整篇文章放在一个根 section 内，发布所需的全部视觉样式内联在该子树的元素上，不依赖页面级样式或脚本：

- 画布 `width:100%;max-width:677px;margin:0 auto`，中文系统字体（PingFang SC、Microsoft YaHei 等）；
- 标签保守使用 `section`、`p`、`span`、`strong`、`br`、`img`；flex 等复杂布局仅当视觉收益能在公众号粘贴后存活时使用；
- 图片 `display:block;width:100%;height:auto;border:0`，带 width/height/alt；纯图容器用 `line-height:0` 消除基线空隙，图注恢复正常行高；
- 用 background-color、边框、留白和字级做结构，避免脆弱的装饰性背景、负 margin 和复杂定位。

## 云端执行边界

`compose_html` 编写文章文档，图片通过当前工具提供的资源别名引用，不使用外部 URL 或内嵌 data URI。执行工具按白名单清洗文档：script、按钮、表单控件、contenteditable、draggable 与 data-* 审阅属性都会被拒绝，因此不要构造本地审阅壳（工具栏、拖拽排序面板、剪贴板脚本）；文章子树本身就是交付物，交付后在用户侧直接审阅、编辑文字和复制。`render_html` 输出整页与切片截图用于检查。

## 完成标准

文章读来连贯；每张配图都有明确的编辑角色；文字始终是可编辑的 HTML 文本，运营事实逐字保留；文章子树复制时只带出内联样式与图片，不依赖任何页面级样式、类名或脚本。
