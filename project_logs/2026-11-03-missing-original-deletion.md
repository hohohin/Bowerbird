# 2026-11-03：原件缺失导致无法删除素材

## 诊断与决定

用户反馈删除时出现「找不到所需文件，可能已被移动或删除。请重新选择文件」，并询问是否由开发版导致。沿 `CanvasAssetDeleteDialog → preview_asset_originals → asset_original` 排查：提示由公共 `userError.ts` 转换 `Io(NotFound)`；原件预览先检查 `assets.store_path`，缺失即拒绝整个选择。此路径没有开发版专属条件；Windows Shell 前缀兼容已经存在，系统回收失败使用另一条提示。

仅以 SQLite `mode=ro`／`query_only` 检查当前配置库路径和文件存在性，没有执行原件预览命令、读取创作内容或清理真实记录。当时 schema 51，844 条可见记录中 62 条登记的本机原件路径不存在；已检视样本仍有缩略图，主要指向旧资料目录。第一次统计误把 Windows 扩展路径当作共享路径跳过，随后修正并核查全部 844 条，未使用第一次的零结果作为结论。没有获知用户此次选中的具体资产，不能断言每条相同提示都必然来自这一批；已用隔离文件复现相同报错。

复用既有原件确认、回收 IPC、公共列表可见性和成功索引恢复入口。文件缺失不能拿缓存或历史别名代替原件删除；采用明确的失效条目清理，保留原件之外的长期资料。沿原确认框调整状态和文案，没有重做布局，不增加自动批量清理。用户对上一轮含其他任务提交的推送范围尚未回复，本轮保持本地提交。
