# 2026-11-01 截图后台唤起与纯图钉住

本轮为源码修改，未重启正式桌面、发布安装包或访问用户素材库。

## 操作及原因

1. 按 ub-mode 阅读当前约定、架构、UI 与错误提示规范，追溯 `2026-10-15.md` 的 Snipaste 静态分析结论：已有独立入口、隐藏预热、PNG 内存传输及分层画布。本机聊天检索未定位原 REA 分析对话，不将历史摘要冒充原始逆向证据。
2. 审查原生全局快捷键与窗口归属：原来已经是系统注册、独立置顶窗口，没有“只能在 main 聚焦时截图”的判断。Windows 的 Wry 不支持 `background_throttling`；隐藏前端原先等待 `Image.decode()`，之后才请求显示。
3. 先做故障注入：让 `decode()` 始终不返回，旧页面不能显示；改为图片 `load` 事件，绘制后在 layout effect 请求显示，回归通过。保留会话身份与旧结果拒绝，取消后仍清空图片与画布。这个测试证明消除了等待依赖，不等于重现了用户电脑上所有后台失败原因。
4. 将已冻结屏幕的交付提取为同一生产函数供原生夹具复用；PNG 编码移到帧互斥锁之外，避免多屏时下一张编码阻塞主线程的取图／显示 IPC。继续先冻结所有屏幕再显示，不缓存上次屏幕内容。
5. 红灯确认 32×24 贴图原来产生 180×120 窗口；去掉 40px 工具栏空间与前端边框。进一步原生验证发现 Windows 自身仍限制最小尺寸，补 `min_inner_size(1, 1)`，并在创建完成、仍隐藏时重新应用图片尺寸，禁用系统拉边框和阴影，Windows 使用透明背景。按图片比例创建、滚轮调整，独立置顶。
6. 删除常驻贴图栏，保留复制／保存键盘操作和 Esc；鼠标移动超过 4px 再原生拖窗，使双击可关闭；中键还原尺寸。截图选区与六类标注工具不改版。
7. 测试完成后只提交本轮代码、夹具与记录；未清理别的任务工作树。当前没有 crapper/dryer/mutator 工具，采用针对性回归和 diff 审查。

## 验证

- `node scripts/screenshot-ui.test.mjs`：全部通过。包括隐藏加载故障、预热／复用、旧会话拒绝、选区与像素操作、六类标注、输出取消／重试、80×60 小图无框、透明根、拖动阈值、双击、滚轮、中键、复制保存和 Esc。
- `pnpm exec tsc --noEmit`、`pnpm exec vite build --outDir .tmp/screenshot-20261101-build` 通过；保留原有大 chunk 提示。
- `screenshot_smoke`：独立临时设置、真实系统快捷键注册／换绑／回退与后台键盘事件，以及小图原生尺寸、窗口标志、图片归属、预热清理。
- `screenshot_webview_smoke`：加载真实截图前端，主窗口全程隐藏；原生置顶／无装饰／比例尺寸，Windows 系统鼠标双击关闭（验证测试窗口焦点后注入并恢复光标位置），合成 4K 截图交付两轮和取消清理。
- 本机开发构建的一次原生观测：钉图准备至可见 **320 ms**；合成 3840×2160 图片编码、IPC、绘制至显示两轮 **265／275 ms**。最终尺寸修复后复跑：钉图 284 ms，4K 两轮 208／214 ms。以上均不含真实系统抓屏，不作为跨设备耗时承诺或修改前后提速百分比。WebView 退出时输出一次类注销 1412 诊断，测试退出码为 0。

原生夹具使用独立 identifier、临时设置及隔离 WebView 配置，不截图真实屏幕、不读写剪贴板、账号或素材库。测试服务端口为 17961。运行：先在 apps/desktop 启动 `pnpm exec vite --host 127.0.0.1 --port 17961 --strictPort`，再执行 `cargo run --locked --offline --manifest-path apps/desktop/src-tauri/Cargo.toml --example screenshot_webview_smoke`；另一个原生夹具为 `--example screenshot_smoke`。

## 边界

真实 F1/F3 是否被其他软件占用、用户长期最小化后的唤起、多屏混合 DPI、Mac 原生仍需对应环境验收。全局快捷键测试使用独立组合键，不抢占真实 F1/F3。

本轮对齐快速唤起、后台工作和纯图置顶的关键链路；并非 Snipaste 全功能等价。窗口／控件自动吸附、跨屏选区、截图历史、透明度调节、穿透、旋转翻转及贴图分组恢复未在本轮实现。官方行为参照：https://github.com/Snipaste/feedback/wiki/Getting-Started 。
